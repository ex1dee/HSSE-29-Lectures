#### **1. Определение**

**Декартово дерево** — это структура данных, сочетающая свойства **бинарного дерева поиска (БДП)** и **бинарной кучи** (обычно max-кучи).

Каждый узел хранит:

- **`key` (ключ)** — для упорядочивания узлов (слева – меньшие ключи, справа – большие). **Свойство БДП**.
    
- **`priority` (приоритет)** — случайное (или псевдослучайное) число. Упорядочивает узлы **по приоритету** (у родителя приоритет ≥, чем у детей). **Свойство кучи (heap)**.

**Следствие:** Структура дерева однозначно определяется набором пар `(key, priority)`. Если приоритеты случайны и независимы, дерево будет **сбалансированным в среднем**.

#### **2. Ключевые операции: Split и Merge**

Операции выполняются за `O(h)`, где `h` — высота, которая в среднем равна `O(log n)`.

##### **`Split(root, key)` — разделение**

- **Вход:** Корень дерева `root`, ключ-разделитель `X`.
    
- **Выход:** Два дерева `(L, R)`:
    
    - `L` — содержит все узлы с ключами **< `X`**.
        
    - `R` — содержит все узлы с ключами **≥ `X`** (или **> `X`** в зависимости от реализации).
        
- **Алгоритм (рекурсивный):**
    
    1. Если `root == nullptr` → вернуть `(nullptr, nullptr)`.
        
    2. Сравниваем `X` с ключом корня `root->key`.
        
        - **Если `root->key < X`**:
            
            - Весь левый сын и сам корень точно попадают в `L`.
                
            - Рекурсивно сплитим **правое** поддерево: `(L_right, R) = Split(root->right, X)`.
                
            - Подвешиваем `L_right` как правое поддерево к `root`.
                
            - Возвращаем `(root, R)`.
                
        - **Иначе** (`root->key >= X`):
            
            - Весь правый сын и сам корень попадают в `R`.
                
            - Рекурсивно сплитим **левое** поддерево: `(L, R_left) = Split(root->left, X)`.
                
            - Подвешиваем `R_left` как левое поддерево к `root`.
                
            - Возвращаем `(L, root)`.
                
- **Важно:** После присоединения поддерева **могло нарушиться кучевое свойство** (приоритет). Используем операцию `Merge` для восстановления при сборке (в реализациях часто `Split` не нарушает heap property, если спускаться, сравнивая ключи, а не приоритеты).
    

##### **`Merge(L, R)` — слияние**

- **Вход:** Два корректных декартовых дерева `L` и `R`, где **все ключи в `L` < всех ключей в `R`**.
    
- **Выход:** Новое декартово дерево, содержащее все узлы из `L` и `R`.
    
- **Алгоритм (рекурсивный, использует приоритеты):**
    
    1. Если `L == nullptr` → вернуть `R`. Если `R == nullptr` → вернуть `L`.
        
    2. Сравниваем **приоритеты** корней: `L->priority` и `R->priority`.
        
        - **Если `L->priority > R->priority`**:
            
            - Корень `L` остаётся корнем результата (т.к. у него больший приоритет).
                
            - Правое поддерево `L` и всё дерево `R` **уже упорядочены по ключу** (все ключи `L->right` > ключей `L`, но < ключей `R`).
                
            - Рекурсивно мерджим: `L->right = Merge(L->right, R)`.
                
            - Возвращаем `L`.
                
        - **Иначе** (`R->priority >= L->priority`):
            
            - Корень `R` становится корнем.
                
            - Левое поддерево `R` и всё дерево `L` упорядочены.
                
            - Рекурсивно мерджим: `R->left = Merge(L, R->left)`.
                
            - Возвращаем `R`.
                

#### **3. Выразимость других операций через Split и Merge**

- **`Insert(key, priority)`**:
    
    1. `(L, R) = Split(root, key)` (разделяем по вставляемому ключу).
        
    2. Создаём новый узел `Node(key, priority)`.
        
    3. `root = Merge(Merge(L, Node), R)`.
        
- **`Erase(key)`**:
    
    1. `(L, R) = Split(root, key)` (в `R` ключи ≥ `key`).
        
    2. `(M, R) = Split(R, key + 1)` (или `> key`, теперь в `M` только узлы с ключом == `key`).
        
    3. Если нужно удалить один узел — удаляем корень `M` (он и есть искомый узел, т.к. все ключи в `M` равны `key`).
        
    4. `root = Merge(L, R)`.
        
- **`Find(key)`** — обычный поиск в БДП, но можно выразить:
    
    1. `(L, R) = Split(root, key)`.
        
    2. `(M, R) = Split(R, key + 1)`.
        
    3. Если `M` не пусто → ключ найден.
        
    4. Восстанавливаем: `root = Merge(Merge(L, M), R)`.
        
- **`Merge` двух произвольных деревьев** (если ключи могут пересекаться):
    
    1. Если нет гарантии `max(L) < min(R)`, то:
        
        - Выбираем корнем узел с большим приоритетом (скажем, из `L`).
            
        - `(L1, L2) = Split(L, root->key)` (отделяем левую и правую части от корня `L`).
            
        - Рекурсивно мерджим `L1` с левой частью второго дерева, а `L2` — с правой.
            

#### **4. Теорема о высоте (без доказательства)**

**Утверждение:** Если приоритеты каждого узла выбираются независимо и равномерно случайно из достаточно большого множества, то **математическое ожидание глубины** (высоты) декартового дерева с `n` узлами есть `O(log n)`.

- **Следствие:** Ожидаемое время выполнения операций `Split`, `Merge`, `Insert`, `Erase` — `O(log n)`.
    
- **Интуиция:** Случайные приоритеты означают, что дерево по свойству кучи будет устроено как **случайное бинарное дерево поиска**, для которого средняя глубина узла ~ `2 ln n`.
    
- **Важно:** Это **вероятностная** гарантия. В худшем случае (крайне маловероятном) высота может быть `O(n)`, но вероятность такого исхода пренебрежимо мала при случайных приоритетах.

### **Итог: Сравнение с AVL**

|Свойство|**AVL-дерево**|**Декартово дерево (Treap)**|
|---|---|---|
|**Балансировка**|**Детерминированная**, строгая (повороты).|**Вероятностная**, за счёт случайных приоритетов.|
|**Гарантия**|**Строгая** `O(log n)` на операцию.|**Математическое ожидание** `O(log n)`.|
|**Основные операции**|`Find`, `Insert`, `Erase` с балансировкой.|`Split`, `Merge` — **примитивы**, через них выражаются все остальные.|
|**Реализация**|Сложнее, нужно хранить `height`/`bf`, много случаев поворотов.|Проще, нужны только `key` и `priority`, рекурсивные `Split`/`Merge`.|
|**Доп. возможности**|—|Легко реализуются **неявные ключи** (дерево по неявному порядку, а не по ключу).|
