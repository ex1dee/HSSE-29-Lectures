### **1. Бинарное дерево поиска (БДП). Основы**

#### **1. Определение**

**Бинарное дерево поиска (Binary Search Tree, BST)** — это бинарное дерево, для которого выполняются следующие условия (инвариант БДП):

1. У каждого узла есть **ключ** (key).
    
2. **Левый** потомок и все его потомки содержат ключи, **строго меньшие** ключа текущего узла.
    
3. **Правый** потомок и все его потомки содержат ключи, **строго большие** (или большие/равные, в зависимости от реализации) ключа текущего узла.
    
4. Левое и правое поддеревья каждого узла сами являются БДП.
    

**Цель:** Хранение множества элементов с возможностью быстрого поиска, вставки и удаления.

#### **2. Операции**

##### **Find(X) — Поиск**

- **Цель:** Проверить наличие ключа `X` в дереве.
    
- **Алгоритм (рекурсивный/итеративный):**
    
    1. Начинаем с корня (`current = root`).
        
    2. Если `current == nullptr` — ключ не найден.
        
    3. Сравниваем `X` с ключом текущего узла (`current->key`).
        
        - Если `X == current->key` — **успех**, нашли.
            
        - Если `X < current->key` — идём в **левое** поддерево (`current = current->left`).
            
        - Если `X > current->key` — идём в **правое** поддерево (`current = current->right`).
            
    4. Переходим к шагу 2.
        
- **Сложность:** `O(h)`, где `h` — высота дерева. В сбалансированном дереве `h = O(log n)`, в вырожденном (списке) `h = O(n)`.
    

##### **Insert(X) — Вставка**

- **Цель:** Добавить ключ `X` в дерево, сохранив инвариант БДП.
    
- **Алгоритм:**
    
    1. **Найти позицию для вставки** — выполнить `Find(X)`. Если ключ уже есть, вставка часто не производится (множество).
        
    2. Когда `Find` достигает `nullptr` (лист, куда нужно пойти дальше), это место для нового узла.
        
    3. Создать новый узел с ключом `X`.
        
    4. **Привязать новый узел к его родителю.** Нужно помнить родителя во время поиска.
        
        - Если дерево было пустое, новый узел становится корнем.
            
        - Если `X < parent->key` — новый узел становится `parent->left`.
            
        - Если `X > parent->key` — новый узел становится `parent->right`.
            
- **Сложность:** `O(h)` (поиск места + константная вставка).
    

##### **Erase(X) — Удаление**

- **Цель:** Удалить узел с ключом `X`, сохранив инвариант БДП. **Самый сложный случай.**
    
- **Три возможные ситуации для удаляемого узла `Z`:**
    
    1. **У `Z` нет детей (лист).** Просто удаляем узел и обнуляем указатель на него у родителя.
        
    2. **У `Z` есть только один ребёнок.** "Вырезаем" узел `Z`, а его ребёнка "подвешиваем" напрямую к родителю `Z` на место `Z`.
        
    3. **У `Z` есть два ребёнка.** Нельзя просто удалить. Стратегия:
        
        - Найти **последователя (successor)** узла `Z` — это узел с **наименьшим ключом в правом поддереве** `Z`. Или **предшественника (predecessor)** — наибольший ключ в левом поддереве. Пусть это узел `S`.
            
        - **Ключ `Z` заменить на ключ `S`.** Теперь нужно удалить уже узел `S`, который гарантированно имеет **не более одного ребёнка** (у последователя не может быть левого ребёнка, у предшественника — правого).
            
        - Удалить узел `S` по простому сценарию (1 или 2).
            
- **Сложность:** `O(h)`. Основное время уходит на поиск узла и его последователя.

### **2. Бинарное дерево поиска. Дополнительные операции**

#### **1. Определение (расширенное)**

Можно хранить в узлах **дополнительную информацию**, чтобы отвечать на более сложные запросы.

- **`size`** — размер поддерева с корнем в данном узле. Позволяет искать порядковую статистику.
    
    - `size = size(left) + size(right) + 1`
        
- **`height`** — высота поддерева. Для балансировок (AVL, красно-чёрные деревья).
    

#### **2. Поиск k-й порядковой статистики (Order Statistics)**

- **Задача:** Найти элемент, который будет стоять на **k-й позиции (0-based или 1-based)** в отсортированном порядке всех ключей дерева.
    
- **Предусловие:** В каждом узле хранится поле `size` — число вершин в его поддереве.
    
- **Алгоритм (для k в 0-based индексации):**  
    Пусть в текущем узле `root`:
    
    - `leftSize = size(root->left)` — количество узлов в левом поддереве.
        
    
    1. Если `k < leftSize`, то искомая статистика находится в **левом** поддереве. Ищем её там рекурсивно.
        
    2. Если `k == leftSize`, то искомая статистика — это ключ в **текущем** узле (`root->key`).
        
    3. Если `k > leftSize`, то искомая статистика находится в **правом** поддереве. В нём мы ищем уже `(k - leftSize - 1)`-ю порядковую статистику (минусуем всех, кто левее).
        
- **Пример (k=3, 0-based):**
    
    text
    
        Узел: key=10, size=7
               /       \
    leftSize=3         size=3
    (1,5,7)            (15,12,18)
    
    `k=3` == `leftSize=3` → ответ `10`.
    
- **Сложность:** `O(h)`.
    

#### **3. LowerBound (верхняя граница) / UpperBound**

- **`LowerBound(X)`** — найти **наименьший** ключ в дереве, который **`>= X`**. (Первый, не меньший X).
    
- **`UpperBound(X)`** — найти **наименьший** ключ в дереве, который **`> X`**. (Первый, строго больший X). Часто используется для поиска диапазонов.
    
- **Алгоритм LowerBound(X) (итеративный):**
    
    1. Начинаем с корня. `current = root`, `candidate = nullptr` (текущий кандидат в ответ).
        
    2. Пока `current != nullptr`:
        
        - Если `X == current->key` — **нашли точное совпадение**, оно и есть ответ. Можно сразу вернуть `current->key`.
            
        - Если `X < current->key` — ключ `current` **потенциально подходит** (`current->key >= X`). Запоминаем его как `candidate`. Пытаемся найти что-то лучше, уходя **влево** (`current = current->left`).
            
        - Если `X > current->key` — ключ `current` слишком мал, идём **вправо** (`current = current->right`) искать большие ключи.
            
    3. По окончанию цикла возвращаем `candidate` (может быть `nullptr`, если все ключи `< X`).
        
- **Алгоритм UpperBound(X)**: Аналогичен, но условие сменяется на строгое: ищем первый ключ `> X`. В случае `X == current->key` идём **вправо**.
    
- **Сложность:** `O(h)`.
