## 1. Поиск за $\mathcal{O}(n \log n)$ (Разделяй и властвуй)

### Зачем нужен алгоритм

**Дано:** Множество из $n$ точек на плоскости $P = \{p_1, p_2, \dots, p_n\}$.

**Найти:** Пару точек $p_i, p_j$ ($i \neq j$), расстояние между которыми минимально.

При прямом переборе (сравнении каждых двух точек) алгоритм требует $\mathcal{O}(n^2)$ времени. Подход «Разделяй и властвуй» позволяет снизить асимптотику до $\mathcal{O}(n \log n)$.

### Суть и корректность алгоритма

1. **Препроцессинг:** Сортируем исходный массив точек по координате $x$. Пусть это будет массив $P_x$. Также создадим копию массива, отсортированную по координате $y$ — $P_y$.
    
2. **Разделение (Divide):** Находим среднюю точку по координате $x$ и проводим вертикальную прямую $x = mid$. Эта прямая делит множество точек на две примерно равные части: левую $L$ и правую $R$.
    
3. **Рекурсия (Conquer):** Рекурсивно находим минимальное расстояние в левой части ($h_L$) и в правой части ($h_R$). Пусть текущее минимальное расстояние будет $h = \min(h_L, h_R)$.
    
4. **Объединение (Combine):** Ближайшая пара точек может оказаться такой, что одна точка лежит в $L$, а другая — в $R$. Очевидно, они должны находиться на расстоянии меньше $h$ друг от друга.
    
    - Отберем только те точки, расстояние от которых до разделяющей прямой по оси $x$ меньше $h$. Они образуют вертикальную полосу шириной $2h$.
        
    - Отсортируем точки внутри этой полосы по координате $y$ (это можно сделать за линейное время, выбрав их из заранее подготовленного массива $P_y$).
        
    - Бежим по отсортированным точкам полосы. Для каждой точки достаточно сравнить её только со следующими за ней точками.
        

> [!INFO] **Геометрическое ограничение (Лемма о разреженности)**
> 
> Сколько точек из одной половины может попасть в прямоугольник полосы размером $h \times 2h$? Так как в каждой из половин (левой и правой) между любыми точками расстояние уже как минимум $h$, то в таком прямоугольнике может поместиться **не более 7 точек** (в худшем случае — 8).
> 
> Следовательно, во внутреннем цикле для каждой точки нам достаточно проверить лишь **7 следующих за ней точек** по оси $y$. Внутренний перебор выполняется за $\mathcal{O}(1)$.

### Асимптотика

- **Временная сложность:** $\mathcal{O}(n \log n)$.
    
    Разделение массива и рекурсивные вызовы описываются классическим уравнением: $T(n) = 2T(n/2) + \mathcal{O}(n)$. По мастер-теореме это дает $\mathcal{O}(n \log n)$. Важно эффективно поддерживать сортировку по $y$ на этапе слияния (как в сортировке слиянием), не запуская `std::sort` на каждом шаге рекурсии.
    
- **Пространственная сложность:** $\mathcal{O}(n)$ для хранения временных массивов при слиянии.
    

### Пример кода (C++)

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>

struct Point {
    double x, y;
};

bool compare_x(const Point& a, const Point& b) { return a.x < b.x; }
bool compare_y(const Point& a, const Point& b) { return a.y < b.y; }

double dist(const Point& a, const Point& b) {
    return std::sqrt((a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y));
}

// Рекурсивная функция
double closest_pair_rec(const std::vector<Point>& P_x, const std::vector<Point>& P_y, int l, int r) {
    if (r - l <= 3) { // База рекурсии: для малого числа точек ищем перебором
        double min_d = 1e18;
        for (int i = l; i < r; ++i)
            for (int j = i + 1; j < r; ++j)
                min_d = std::min(min_d, dist(P_x[i], P_x[j]));
        return min_d;
    }

    int mid = l + (r - l) / 2;
    Point mid_point = P_x[mid];

    // Разделяем P_y на две части для сохранения порядка по y
    std::vector<Point> P_y_L, P_y_R;
    P_y_L.reserve(mid - l);
    P_y_R.reserve(r - mid);
    for (const auto& p : P_y) {
        if (p.x < mid_point.x || (p.x == mid_point.x && p.y < mid_point.y)) 
            P_y_L.push_back(p);
        else 
            P_y_R.push_back(p);
    }

    double dl = closest_pair_rec(P_x, P_y_L, l, mid);
    double dr = closest_pair_rec(P_x, P_y_R, mid, r);
    double h = std::min(dl, dr);

    // Сборка точек в полосе шириной 2h
    std::vector<Point> strip;
    for (const auto& p : P_y) {
        if (std::abs(p.x - mid_point.x) < h) {
            strip.push_back(p);
        }
    }

    // Проверка точек в полосе (не более 7 сравнений для каждой)
    for (size_t i = 0; i < strip.size(); ++i) {
        for (size_t j = i + 1; j < strip.size() && (strip[j].y - strip[i].y) < h; ++j) {
            h = std::min(h, dist(strip[i], strip[j]));
        }
    }

    return h;
}

double get_closest_dist(std::vector<Point> P) {
    std::vector<Point> P_x = P;
    std::vector<Point> P_y = P;
    std::sort(P_x.begin(), P_x.end(), compare_x);
    std::sort(P_y.begin(), P_y.end(), compare_y);
    return closest_pair_rec(P_x, P_y, 0, P.size());
}
```

## 2. Поиск за $\mathcal{O}(n)$ в среднем (Рандомизированный алгоритм Рабина)

### Суть алгоритма

Алгоритм Рабина использует хеш-таблицу (сетку) и случайную перестановку точек, достигая линейного времени работы **в среднем** (математическое ожидание).

1. **Рандомизация:** Перемешиваем массив точек случайным образом: $p_1, p_2, \dots, p_n$.
    
2. **Инициализация:** Положим начальное минимальное расстояние $h = dist(p_1, p_2)$.
    
3. **Построение сетки:** Разобьем плоскость на квадратную сетку с размером ячейки $h \times h$. Каждую точку из уже обработанных распределим по ячейкам. Координаты ячейки для точки $(x, y)$ вычисляются как $\left(\lfloor \frac{x}{h} \rfloor, \lfloor \frac{y}{h} \rfloor\right)$. В качестве структуры данных используется хеш-таблица, где ключ — координаты ячейки, а значение — список точек в ней.
    
4. **Итеративный проход:** Поочередно добавляем точки $p_i$ (начиная с $p_3$):
    
    - Определяем, в какую ячейку попадает текущая точка $p_i$.
        
    - Проверяем саму ячейку и **8 её соседей** (всего 9 ячеек).
        
    - Если расстояние от $p_i$ до какой-то из старых точек оказывается меньше текущего $h$, то мы нашли новое минимальное расстояние: $h_{new} < h$.
        
    - **Перестройка сетки (Рехэширование):** Если $h$ уменьшилось, старая сетка становится неактуальной. Мы полностью уничтожаем хеш-таблицу, меняем размер ячейки на новый $h = h_{new}$ и заново передобавляем все предыдущие точки $p_1 \dots p_{i}$ в новую сетку за линейное время $\mathcal{O}(i)$.
        
    - Если расстояние не уменьшилось, просто добавляем точку $p_i$ в текущую сетку за $\mathcal{O}(1)$.
        

### Корректность и обоснование асимптотики

> [!INFO] **Почему это работает за $\mathcal{O}(n)$?**
> 
> Если мы просто добавляем точку без изменения $h$, это занимает $\mathcal{O}(1)$, так как в каждой ячейке сетки размера $h \times h$ может находиться не более 4 точек (иначе расстояние между ними было бы меньше $h$, что невозможно). Значит, в 9 соседних ячейках суммарно находится константное число точек.
> 
> Перестройка сетки за $\mathcal{O}(i)$ происходит крайне редко. Вероятность того, что $i$-я точка уменьшит текущее минимальное расстояние, равна $\frac{2}{i}$ (так как только 2 точки из первых $i$ образуют текущую ближайшую пару).
> 
> Математическое ожидание стоимости добавления $i$-й точки равно:
> 
> $$\mathcal{O}(1) \cdot \left(1 - \frac{2}{i}\right) + \mathcal{O}(i) \cdot \frac{2}{i} = \mathcal{O}(1) + \mathcal{O}(1) = \mathcal{O}(1)$$
> 
> Суммируя по всем $n$ точкам, получаем общее среднее время работы **$\mathcal{O}(n)$**.

## Сравнение

|**Алгоритм**|**Сложность в худшем случае**|**Сложность в среднем**|**Тип алгоритма**|**Рекомендация**|
|---|---|---|---|---|
|**Разделяй и властвуй**|$\mathcal{O}(n \log n)$|$\mathcal{O}(n \log n)$|Детерминированный|Надежный, легко реализуется без хэш-таблиц.|
|**Алгоритм Рабина**|$\mathcal{O}(n^2)$ (при плохих хэш-коллизиях)|$\mathcal{O}(n)$|Рандомизированный|Быстрее на практике для огромных массивов, но требует хорошей хэш-функции.|
