## 1 таск: Целостность данных
### 1. Модель данных (Postgres)

Необходимо расширить сущность файла следующими полями:

- **`status`**: `PENDING`, `ERROR`, `READY`, `FATAL`.
    
- **`operation_type`**: `UPLOAD`, `DELETE`, `CHANGE_METADATA` (заполняется только для операций записи).
    
- **`started_at`**: Timestamp начала операции.
    
- **`updated_at`**: Timestamp "пульса" (обновлять при каждом чанке или успешном шаге).
    
- **`retry_count`**: Счетчик попыток (default 0).
    
- **`error_message`**: Текст последней ошибки.
    

### 2. Правила доступа (Контроль состояний)

- **Блокировка:** Если `status != READY`, любые новые операции записи (`UPLOAD`, `DELETE`, `CHANGE_METADATA`) запрещены (возвращаем ошибку/конфликт).
    
- **Чтение:** Операции `READ` (получение списка, скачивание) разрешены **только** для файлов в статусе `READY`.
    

### 3. Жизненный цикл операции

1. **Старт:** Перед началом любой операции записи ставим `FileEntity` статус `PENDING` и соответствующим `operation_type`.
    
2. **Процесс:** В ходе выполнения (особенно при загрузке чанками) обновляем `updated_at`.
    
3. **Финал:** 
	* При успехе: статус -> `READY`, `operation_type` -> `null`.
    
    - При ошибке: статус -> `ERROR`, записываем короткое `error_message`.
        

### 4. Фоновая очистка (Cleanup Task)

Реализовать периодическую задачу `@Scheduled`, которая обрабатывает "зависшие" файлы (где `updated_at` устарел):

- **UPLOAD:** Если статус `PENDING` или `ERROR` — **Hard Delete** (удаляем запись в БД и ошметки в S3).

## 3 таск: Обработка ошибок в `MinIO`

Создать метод-обёртку всех методов в `Minio` и в нём обрабатывать все исключения:
```java
private <T> T execute(Callable<T> callable) { 
	try {
		return callable.call(); 
	} catch ...
}
```

___

Разделим (условно) ошибки:

#### 1. Временные — `RecoverableStorageException`

В `Repository` ловим это исключение и ставим статус `ERROR`

- `ExecutionException` с `cause != ErrorResponseException`
- `IOException` – проблемы с сетью
- `InsufficientDataException` – поток данных прервался на полпути
- `InternalException` – внутренняя ошибка `MinIO`

#### 2. Критические — `FatalStorageException`

В `Repository` ловим это исключение и ставим статус `FATAL`

- `ExecutionException` с `cause == ErrorResponseException`
- Другие — `FatalStorageException`

*В будущем при временных ошибках сделаем `Retry`*
