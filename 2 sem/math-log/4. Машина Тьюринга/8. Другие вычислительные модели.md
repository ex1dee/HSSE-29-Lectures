## Random Access Machine (RAM)

- **Random Access Machine (RAM)** — абстрактная вычислительная модель, моделирующая работу классического компьютера с возможностью адресации памяти.
    
- Память RAM состоит из трех бесконечных лент (вход, память, выход), разбитых на ячейки. В каждой ячейке хранится ровно одно целое число.
    
- **Адресация и операнды:** операнд $u$ в командах интерпретируется в зависимости от типа префикса:
    
    - Константа (`=i`): Значение $v(u) = i$.
        
    - Прямая адресация (`i`): Значение $v(u) = r(i)$ — содержимое ячейки $i$.
        
    - Косвенная адресация (`*i`): Значение $v(u) = r(r(i))$ — значение из ячейки, адрес которой хранится в ячейки $i$ (указатель).
        
- **Состояние (конфигурация):** задается четверкой $(n, x, r, y)$, где $n \in \mathbb{N}$ — счетчик команд, а $x, r, y$ — векторы состояний входа, памяти и выхода соответственно.
    

> [!INFO] **Утверждение (о счётности множества RAM-машин)**
> 
> Множество всех возможных программ для Random Access Machine счётно.

**Доказательство:**

Каждая команда RAM описывается конечным числом символов (наименование, тип операнда, числовой операнд). Программа RAM представляет собой конечную последовательность таких команд. Следовательно, любую RAM-программу можно закодировать конечной строкой текста в фиксированном конечном алфавите. Множество всех конечных слов в конечном алфавите счётно, а значит, и подмножество синтаксически корректных программ RAM также является счётным.

### Команды-операции RAM

Для всех операций по умолчанию детерминированно устанавливается счетчик $n' = n + 1$.

|**Команда**|**Математическое действие**|**Описание**|
|---|---|---|
|`store u`|$r'(v(u)) = r(0)$|Записать содержимое аккумулятора (ячейки 0) в ячейку с адресом $v(u)$.|
|`load u`|$r'(0) = r(v(u))$|Загрузить значение из ячейки $v(u)$ в аккумулятор.|
|`add u`|$r'(0) = r(0) + v(u)$|Сложение значения аккумулятора со значением $v(u)$.|
|`sub u`|$r'(0) = r(0) - v(u)$|Вычитание значения $v(u)$ из аккумулятора.|
|`mul u`|$r'(0) = r(0) \times v(u)$|Умножение аккумулятора на значение $v(u)$.|
|`div u`|$r'(0) = \lfloor r(0)/v(u) \rfloor$|Целочисленное деление аккумулятора на $v(u)$.|
|`read u`|$r'(0) = x(v(u))$|Считать значение из входной ленты по индексу $v(u)$ в аккумулятор.|
|`write u`|$y'(v(u)) = r(0)$|Записать значение из аккумулятора на выходную ленту по индексу $v(u)$.|

### Команды-переходы RAM

Данные команды управляют исключительно счётчиком команд $n'$:

- `goto u` — безусловный переход:
    
    $$n' = v(u)$$
    
- `ifzero u` — условный переход по нулю:
    
    $$n' = \begin{cases} v(u), & \text{если } r(0) = 0 \\ n + 1, & \text{если } r(0) \neq 0 \end{cases}$$
    
- `ifpos u` — условный переход по положительному значению:
    
    $$n' = \begin{cases} v(u), & \text{если } r(0) > 0 \\ n + 1, & \text{если } r(0) \le 0 \end{cases}$$

## Машины Минского (Регистровые машины)

- **Машина Минского** — вычислительная модель, содержащая конечное число регистров $R_1, R_2, \dots, R_n$, каждый из которых способен хранить произвольное неотрицательное целое число.
    
- Машина управляется фиксированной программой со строго ограниченным базисом из 3 типов команд.
    

### Базис команд Машины Минского

- `inc i, j` — инкремент: увеличить значение регистра $R_i$ на 1 и передать управление команде $j$.
    
- `dec i, j, k` — декремент с ветвлением: если $v(i) = 0$, то передать управление команде $j$. В противном случае уменьшить значение регистра $R_i$ на 1 и передать управление команде $k$.
    
- `halt` — безусловный останов вычислительного процесса.
    

> [!EXAMPLE] **Примеры программ для Машины Минского**
> 
> **1. Обнуление регистра $R_i$:**
> 
> ```d
> 1: dec i, n, 1  // Если R_i == 0, выходим на команду n. Иначе уменьшаем и возвращаемся на строку 1.
> ```
> 
> **2. Копирование содержимого регистра $R_i$ в регистр $R_j$ с использованием вспомогательного регистра $R_k$:**
> 
> ```d
> 1: dec i, 4, 2  // Опустошаем R_i. Если пуст — переходим к шагу восстановления (строка 4)
> 2: inc j, 3     // Увеличиваем целевой регистр R_j
> 3: inc k, 1     // Сохраняем копию в бэкап-регистр R_k, возвращаемся на шаг 1
> 4: dec k, n, 5  // Восстанавливаем исходный регистр R_i из R_k
> 5: inc i, 4
> ```
> 
> **3. Проверка чётности регистра $R_i$:**
> 
> ```d
> 1: dec i, n, 2  // Если R_i == 0 (число четное), переход на n
> 2: dec i, m, 1  // Если после вычитания 1 регистр стал 0 (число нечетное), переход на m. Иначе на шаг 1.
> ```

## Нормальные алгорифмы Маркова (НАМ)

- **Нормальный алгорифм Маркова** — это система преобразования строк, основанная на упорядоченном наборе правил подстановки над конечным алфавитом $A$.
    
- **Схема алгорифма:** конечная последовательность правил двух видов:
    
    1. Простая подстановка: $u \to v$
        
    2. Заключительная подстановка: $u \to \cdot v$ (означает немедленный останов после выполнения).
        

### Логика работы НАМ

На каждом дискретном шаге времени текущая строка трансформируется по следующему строгому алгоритму:

1. В схеме правил сверху вниз ищется **самое первое** правило $u \to v$ (или $u \to \cdot v$), для которого подслово $u$ входит в текущую рабочую строку.
    
2. Если такое правило найдено, осуществляется замена **самого левого** вхождения подслова $u$ на строку $v$.
    
3. Если сработавшее правило было _заключительным_ ($u \to \cdot v$), алгорифм **завершает работу**.
    
4. Если ни одно из правил схемы применить невозможно, алгорифм **завершает работу** по причине остановки из-за отсутствия применимых правил.
    

> [!EXAMPLE] **Пример работы алгорифма Маркова**
> 
> Пусть задан алфавит $A = \{a, b\}$ и схема правил:
> 
> 1. $ab \to ba$
>     
> 2. $b \to \cdot a$
>     

**Обоснование примера^**

Запустим НАМ на входной строке $w = bab$:

- Шаг 1: Правило 1 не применимо. Применяется правило 2 к самому левому $b$: $\underline{b}ab \to \mathbf{a}ab$.
    
- Шаг 2: Правило 1 применимо к подстроке $ab$: $a\underline{ab} \to a\mathbf{ba}$.
    
- Шаг 3: Правило 1 применимо к подстроке $ab$: $\underline{ab}a \to \mathbf{ba}a$.
    
- Шаг 4: Правило 1 не применимо. Применяется заключительное правило 2 к самому левому $b$: $\underline{b}aa \to \cdot \mathbf{a}aa$.
    

Алгорифм завершает работу, так как сработало заключительное правило. Итоговый результат: $aaa$.
