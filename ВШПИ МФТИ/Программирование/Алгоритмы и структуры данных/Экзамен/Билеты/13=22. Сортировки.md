### **13. Сортировки. Теорема о нижней границе времени сортировки. Стабильные сортировки**

**Сортировка** — процесс упорядочивания элементов последовательности по возрастанию (или убыванию).  
**Устойчивость (стабильность)** — свойство сортировки сохранять относительный порядок элементов с одинаковыми ключами.

**Пример устойчивости**:  
Исходный массив пар (ключ, значение):  
`(2, A), (1, B), (2, C)`  
После устойчивой сортировки по ключу:  
`(1, B), (2, A), (2, C)` — порядок (A, C) сохранён.  
После неустойчивой: возможен порядок `(1, B), (2, C), (2, A)`.

**Стабильные алгоритмы**:

- Сортировка вставками
    
- Сортировка слиянием
    
- Сортировка подсчётом (правильная реализация)
    
- LSD-сортировка
    

**Нестабильные алгоритмы**:

- Быстрая сортировка
    
- Пирамидальная сортировка
    
- Сортировка выбором
    

---

**Теорема о нижней границе времени сортировки сравнениями**:

_Формулировка_: Любой алгоритм сортировки, основанный на попарном сравнении элементов, имеет нижнюю оценку времени работы **Ω(n log n)** в худшем случае.

_Доказательство (без деталей)_:

1. Имеется n! возможных перестановок исходного массива.
    
2. Каждое сравнение даёт 2 возможных исхода, поэтому можно представить процесс как бинарное дерево решений.
    
3. Для однозначного определения правильной перестановки необходимо сделать не менее log₂(n!) сравнений.
    
4. По формуле Стирлинга:  
    log₂(n!) ≈ n log₂ n - n log₂ e + O(log n) = Θ(n log n)
    

_Следствие_: Алгоритмы, работающие за O(n log n) (слиянием, пирамидальная), являются асимптотически оптимальными среди сортировок сравнениями.

### **14. Сортировка слиянием. Подсчёт числа инверсий**

**Сортировка слиянием (Merge Sort)**:

_Алгоритм_:

1. Рекурсивно разделяем массив на две примерно равные части
    
2. Сортируем каждую часть рекурсивно
    
3. Сливаем две отсортированные части в одну
    

_Слияние двух отсортированных массивов_:

- Используем два указателя, идущих от начала каждого массива
    
- На каждом шаге выбираем меньший из текущих элементов
    
- Время слияния: O(n)
    

_Время работы_:  
T(n) = 2T(n/2) + O(n) ⇒ T(n) = O(n log n) (по теореме о рекурсии)

_Память_: O(n) (требуется дополнительный массив для слияния)  
_Стабильность_: Да, если при равенстве элементов брать из левой части

---

**Подсчёт числа инверсий**:

_Определение_: Инверсия — пара индексов (i, j), где i < j, но a[i] > a[j].

_Модификация сортировки слиянием для подсчёта инверсий_:

1. При рекурсивном вызове считаем инверсии в левой и правой частях
    
2. При слиянии: если элемент из правой части меньше текущего элемента из левой, то он образует инверсии со всеми оставшимися элементами левой части
    
3. Суммируем все три количества
    

_Пример_:

text

Левый массив: [3, 5, 7] (уже отсортирован)
Правый массив: [2, 4, 6] (уже отсортирован)
При слиянии: 2 < 3 → образует инверсии с [3, 5, 7] → +3 инверсии

_Время работы_: O(n log n), так как это та же сортировка слиянием с дополнительным O(1) действий при каждом слиянии.

_Код (идея)_:

python

def count_inversions(arr):
    if len(arr) <= 1:
        return arr, 0
    
    mid = len(arr) // 2
    left, inv_left = count_inversions(arr[:mid])
    right, inv_right = count_inversions(arr[mid:])
    
    merged = []
    i = j = 0
    inv_split = 0
    
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            inv_split += len(left) - i  # все оставшиеся в left больше right[j]
            j += 1
    
    merged.extend(left[i:])
    merged.extend(right[j:])
    
    return merged, inv_left + inv_right + inv_split

### **15. Бинарная пирамида (куча). Определение. Поддержка свойства пирамиды**

**Бинарная пирамида (куча)** — это полное бинарное дерево, удовлетворяющее свойству пирамиды:

- Для max-heap: значение в каждом узле ≥ значений в его потомках
    
- Для min-heap: значение в каждом узле ≤ значений в его потомках
    

**Представление в массиве** (0-индексация):

- Корень: индекс 0
    
- Для элемента с индексом i:
    
    - Левый потомок: 2i + 1
        
    - Правый потомок: 2i + 2
        
    - Родитель: ⌊(i-1)/2⌋
        

**Полнота дерева**: все уровни, кроме последнего, полностью заполнены; последний уровень заполняется слева направо.

---

**Поддержка свойства пирамиды**:

1. **SiftUp (просеивание вверх)**:
    
    - Применяется, когда элемент может быть больше родителя (для max-heap)
        
    - Пока элемент больше родителя, меняем их местами
        
    - Поднимаемся к корню
        
    
    python
    
    def sift_up(heap, idx):
        while idx > 0 and heap[idx] > heap[(idx-1)//2]:
            heap[idx], heap[(idx-1)//2] = heap[(idx-1)//2], heap[idx]
            idx = (idx-1)//2
    
    Время: O(log n)
    
2. **SiftDown (просеивание вниз)**:
    
    - Применяется, когда элемент может быть меньше одного из потомков
        
    - Пока элемент меньше какого-либо потомка, меняем с наибольшим потомком
        
    - Опускаемся до листьев
        
    
    python
    
    def sift_down(heap, idx, size):
        while 2*idx + 1 < size:
            left = 2*idx + 1
            right = 2*idx + 2
            largest = left
            
            if right < size and heap[right] > heap[left]:
                largest = right
            
            if heap[idx] >= heap[largest]:
                break
            
            heap[idx], heap[largest] = heap[largest], heap[idx]
            idx = largest
    
    Время: O(log n)
    

---

### **16. Бинарная пирамида. Основные операции**

1. **Вставка элемента**:
    
    - Добавляем элемент в конец массива (на последнюю позицию последнего уровня)
        
    - Вызываем SiftUp для восстановления свойства пирамиды
        
    - Время: O(log n)
        
2. **Извлечение максимума (для max-heap)**:
    
    - Сохраняем значение корня
        
    - Перемещаем последний элемент в корень
        
    - Уменьшаем размер кучи
        
    - Вызываем SiftDown для корня
        
    - Возвращаем сохранённое значение
        
    - Время: O(log n)
        
3. **Увеличение/уменьшение ключа**:
    
    - Изменяем значение элемента
        
    - Если значение увеличилось → SiftUp
        
    - Если уменьшилось → SiftDown
        
    - Время: O(log n)
        
4. **Удаление произвольного элемента**:
    
    - Увеличиваем его ключ до ∞ (для max-heap)
        
    - Вызываем SiftUp, чтобы поднять элемент в корень
        
    - Извлекаем максимум
        
    - Время: O(log n)
        
5. **Построение кучи из массива (Heapify)**:
    
    - Вызываем SiftDown для всех элементов от ⌊n/2⌋ до 0
        
    - Время: O(n) (б/д)
        

---

### **17. Heapify (O(n)) и пирамидальная сортировка**

**Heapify — построение кучи за O(n)**:  
_Алгоритм_:

1. Берём произвольный массив
    
2. Для всех i от ⌊n/2⌋ до 0 (в обратном порядке):
    
    - Вызываем SiftDown(i)
        

_Почему O(n), а не O(n log n)_:

- Большинство элементов находятся на нижних уровнях и просеиваются на малую высоту
    
- Формально:  
    T(n) ≤ Σ_{h=0}^{log n} (число узлов на высоте h) * O(h)  
    ≤ Σ_{h=0}^{log n} ⌈n/2^{h+1}⌉ * O(h)  
    ≤ O(n * Σ_{h=0}^{∞} h/2^h) = O(n * 2) = O(n)
    

---

**Пирамидальная сортировка (Heap Sort)**:

_Алгоритм_:

1. Построить max-heap из исходного массива (Heapify)
    
2. Для i от n-1 до 1:
    
    - Поменять местами a[0] и a[i] (максимум уходит в конец)
        
    - Уменьшить размер кучи на 1
        
    - Вызвать SiftDown(0) для восстановления кучи
        

_Пример_:

text

Исходный: [4, 10, 3, 5, 1]
Построили кучу: [10, 5, 3, 4, 1]
Шаг 1: [1, 5, 3, 4, 10], SiftDown → [5, 4, 3, 1, 10]
Шаг 2: [1, 4, 3, 5, 10], SiftDown → [4, 1, 3, 5, 10]
Шаг 3: [3, 1, 4, 5, 10], SiftDown → [3, 1, 4, 5, 10]
Шаг 4: [1, 3, 4, 5, 10] - отсортирован

_Характеристики_:

- Время работы: O(n log n) в худшем, среднем и лучшем случае
    
- Память: O(1) (in-place)
    
- Нестабильна
    
- Медленнее быстрой сортировки в среднем, но имеет гарантированную O(n log n)
    

_Оптимизация (Bottom-up Heap Sort)_:

- При SiftDown вместо сравнения с обоими детьми и родителем
    
- Идём только вниз до листа, затем SiftUp
    
- Уменьшает количество сравнений на 20-30%

### **18. Быстрая сортировка. Partition за O(1) доп. памяти. Оценка времени со случайным pivot**

**Быстрая сортировка (Quick Sort)**:

_Основная идея_:

1. Выбрать опорный элемент (pivot)
    
2. Разделить массив на две части: ≤ pivot и > pivot
    
3. Рекурсивно отсортировать каждую часть
    

---

**Процедура Partition за O(1) дополнительной памяти**:

1. **Разбиение Ломуто (Lomuto)**:
    
    python
    
    def partition_lomuto(arr, left, right):
        pivot = arr[right]  # выбираем последний элемент
        i = left  # граница для элементов ≤ pivot
        
        for j in range(left, right):
            if arr[j] <= pivot:
                arr[i], arr[j] = arr[j], arr[i]
                i += 1
        
        arr[i], arr[right] = arr[right], arr[i]
        return i
    
    - Инвариант: arr[left..i-1] ≤ pivot, arr[i..j-1] > pivot
        
    - Всегда делает n-1 сравнений
        
    - Медленнее на практике
        
2. **Разбиение Хоара (Hoare)** — предпочтительнее:
    
    python
    
    def partition_hoare(arr, left, right):
        pivot = arr[(left + right) // 2]  # лучше выбирать середину
        i = left - 1
        j = right + 1
        
        while True:
            i += 1
            while arr[i] < pivot:
                i += 1
            
            j -= 1
            while arr[j] > pivot:
                j -= 1
            
            if i >= j:
                return j
            
            arr[i], arr[j] = arr[j], arr[i]
    
    - Два указателя сходятся к центру
        
    - Меньше обменов в среднем
        
    - Возвращает границу, где левая часть ≤ pivot, правая ≥ pivot
        

---

**Оценка времени работы со случайным pivot**:

_Случайный выбор pivot_: выбираем случайный элемент в качестве опорного.

_Математическое ожидание времени работы_:

1. Пусть X — общее количество сравнений
    
2. Введём индикаторные случайные величины:
    
    - X_ij = 1, если элементы i и j сравнивались
        
    - X_ij = 0 иначе
        
3. Тогда X = Σ_{i<j} X_ij
    
4. Вероятность сравнения i и j: 2/(j-i+1)  
    (элементы сравниваются, если один из них выбран как pivot раньше любого другого между ними)
    
5. M[X] = Σ_{i<j} 2/(j-i+1) = O(n log n)
    

_Итог_:

- O(n log n) в среднем при случайном выборе pivot
    
- O(n²) в худшем случае (редко при случайном выборе)
    
- Константа меньше, чем у сортировки слиянием
    

_Доказательство без деталей_:

- Каждый выбор pivot делит массив на две части
    
- В среднем размер частей пропорционален исходному
    
- Уравнение: T(n) = T(i) + T(n-i-1) + O(n)
    
- В среднем i ≈ n/2 ⇒ T(n) ≈ 2T(n/2) + O(n) ⇒ O(n log n)
    

---

### **19. Поиск порядковой статистики. Оценка времени со случайным pivot**

**Порядковая статистика** — k-й по величине элемент в массиве (k от 1 до n).

**Алгоритм QuickSelect (аналог быстрой сортировки)**:

1. Выбрать случайный pivot
    
2. Выполнить Partition массива
    
3. Определить, в какой части находится k-й элемент:
    
    - Если pivot оказался на позиции k, вернуть его
        
    - Если k меньше индекса pivot, искать в левой части
        
    - Если k больше, искать в правой части
        

python

def quickselect(arr, left, right, k):
    if left == right:
        return arr[left]
    
    pivot_index = partition(arr, left, right)
    
    if k == pivot_index:
        return arr[k]
    elif k < pivot_index:
        return quickselect(arr, left, pivot_index - 1, k)
    else:
        return quickselect(arr, pivot_index + 1, right, k)

---

**Оценка времени работы со случайным pivot**:

_Математическое ожидание_: O(n)

_Интуиция_:

- Каждый шаг уменьшает размер задачи в среднем вдвое
    
- Ожидаемое количество шагов: O(log n)
    
- На каждом шаге обрабатываем часть массива
    
- Общее время: n + n/2 + n/4 + ... = O(n)
    

_Формально (без доказательства)_:

- M[T(n)] ≤ M[T(max(|L|, |R|))] + O(n)
    
- В среднем max(|L|, |R|) ≤ αn для некоторого α < 1
    
- M[T(n)] ≤ O(n) + M[T(αn)] ≤ O(n) + α M[T(n)]
    
- (1-α) M[T(n)] ≤ O(n) ⇒ M[T(n)] = O(n)
    

_Худший случай_: O(n²) (если всегда выбирается минимальный/максимальный элемент)

_Применение_:

- Нахождение медианы (k = n/2)
    
- Нахождение k наименьших/наибольших элементов
    
- Разбиение данных на процентили

### **20. Алгоритм медианы медиан. Время поиска медианы медиан**

**Проблема**: гарантировать линейное время поиска порядковой статистики в худшем случае.

def median_of_medians(arr, left, right, k):
    # Базовый случай
    if right - left < 5:

    # 1. Разбиваем на группы по 5
    medians = []
    for i in range(left, right + 1, 5):
        group_right = min(i + 4, right)
        group_median = median_of_five(arr, i, group_right)
        medians.append(group_median)
    
    # 2. Находим медиану медиан
    mom = median_of_medians(medians, 0, len(medians)-1, len(medians)//2)
    
    # 3. Partition относительно mom
    pivot_index = partition_around(arr, left, right, mom)

    if k == pivot_index:

    elif k < pivot_index:

**Время поиска медианы медиан**:

_Ключевое свойство_: Медиана медиан гарантированно делит массив в соотношении не хуже чем 30/70.

_Доказательство_:

1. Медиан медиан ≥ половине медиан групп
    
2. Каждая такая медиана ≥ 3 элементам своей группы (2 меньших и сама медиана)
    
3. Таким образом, ≥ 30% элементов ≤ pivot и ≥ 30% ≥ pivot
    

_Время работы_:

1. Разделение на группы и поиск медиан: O(n)
    
2. Рекурсивный поиск медианы медиан: T(n/5)
    
3. Partition: O(n)
    
4. Рекурсивный вызов для большей части: ≤ T(7n/10)
    

Рекуррентное соотношение:  
T(n) ≤ T(n/5) + T(7n/10) + O(n)

Докажем по индукции, что T(n) ≤ Cn:  
T(n) ≤ C(n/5) + C(7n/10) + an = C(9n/10) + an

Нужно: C(9n/10) + an ≤ Cn ⇒ an ≤ Cn/10 ⇒ C ≥ 10a

Таким образом, T(n) = O(n)

### **21. Алгоритмы и время работы быстрой сортировки с использованием алгоритма медианы медиан**

**Детерминированная быстрая сортировка с медианой медиан**:

_Алгоритм_:

1. В каждом рекурсивном вызове:
    
    - Находим медиану медиан текущего подмассива
        
    - Используем её как pivot
        
    - Выполняем Partition
        
    - Рекурсивно сортируем обе части
        

_Время работы_:

- Выбор pivot: O(n) с помощью алгоритма медианы медиан
    
- Partition: O(n)
    
- Размеры частей: ≤ 7n/10 и ≥ 3n/10
    

Рекуррентное соотношение:  
T(n) ≤ T(7n/10) + T(3n/10) + O(n)

Это не дает T(n) = O(n log n) напрямую, но если учитывать, что:  
T(n) ≤ max(T(7n/10), T(3n/10)) + O(n) ≤ T(7n/10) + O(n)

Тогда: T(n) = O(n log n) в худшем случае

_Недостатки_:

- Большая константа в O(n) выбора pivot
    
- На практике медленнее рандомизированной версии
    
- Используется редко, в основном как теоретический результат
    

_Оптимизация_ (Интроспективная сортировка — Introsort):

1. Начинаем как быстрая сортировка
    
2. Если глубина рекурсии превышает c log n, переключаемся на пирамидальную
    
3. Для маленьких подмассивов используем сортировку вставками
    
4. Гарантирует O(n log n) в худшем случае с хорошей константой

### **22. Сортировка подсчётом. Стабильный вариант. Алгоритм LSD**

**Сортировка подсчётом (Counting Sort)**:

_Условия_:

- Элементы — целые числа в диапазоне [0, k), где k = O(n)
    
- Или вообще любой малый диапазон
    

_Нестабильный вариант_:

python

def counting_sort_unstable(arr, k):
    count = [0] * k
    for x in arr:
        count[x] += 1
    
    result = []
    for i in range(k):
        result.extend([i] * count[i])
    
    return result

Время: O(n + k), Память: O(k)

**Стабильный вариант**:

_Алгоритм_:

1. Подсчитать количество каждого элемента
    
2. Вычислить префиксные суммы (позиции, где должны начинаться элементы)
    
3. Пройти исходный массив справа налево, размещая элементы по вычисленным позициям
    

python

def counting_sort_stable(arr, k):
    n = len(arr)
    count = [0] * k
    
    # 1. Подсчет
    for x in arr:
        count[x] += 1
    
    # 2. Префиксные суммы (позиции)
    for i in range(1, k):
        count[i] += count[i-1]
    
    # 3. Размещение (справа налево для стабильности)
    result = [0] * n
    for i in range(n-1, -1, -1):
        x = arr[i]
        count[x] -= 1
        result[count[x]] = x
    
    return result

_Почему справа налево_: чтобы сохранить порядок одинаковых элементов.

_Характеристики_:

- Время: O(n + k)
    
- Память: O(n + k)
    
- Стабильна
    
- Не основана на сравнениях

**Алгоритм LSD (Least Significant Digit) — поразрядная сортировка**:

_Идея_: сортировать числа по младшим разрядам к старшим, используя стабильную сортировку подсчётом для каждого разряда.

_Условия_:

- Числа фиксированной разрядности
    
- Или строки одинаковой длины
    

_Алгоритм_:

python

def lsd_sort(arr, d):  # d - количество разрядов
    n = len(arr)
    
    # Проходим по всем разрядам от младшего к старшему
    for digit in range(d):
        # Сортировка подсчетом по текущему разряду
        count = [0] * 10  # для цифр 0-9
        
        # Извлечение digit-й цифры
        for x in arr:
            digit_value = (x // (10**digit)) % 10
            count[digit_value] += 1
        
        # Префиксные суммы
        for i in range(1, 10):
            count[i] += count[i-1]
        
        # Размещение (справа налево)
        result = [0] * n
        for i in range(n-1, -1, -1):
            x = arr[i]
            digit_value = (x // (10**digit)) % 10
            count[digit_value] -= 1
            result[count[digit_value]] = x
        
        arr = result
    
    return arr

_Пример_:

Исходно: [170, 45, 75, 90, 802, 24, 2, 66]
По 0-му разряду: [170, 090, 802, 002, 024, 045, 075, 066]
По 1-му разряду: [802, 002, 024, 045, 066, 170, 075, 090]
По 2-му разряду: [002, 024, 045, 066, 075, 090, 170, 802]

_Время работы_: O(d * (n + k)), где d — количество разрядов, k — основание системы счисления (10 для десятичной)

_Память_: O(n + k)

_Стабильность_: Да (используется стабильная сортировка подсчётом)

_Применение_:

- Сортировка целых чисел
    
- Сортировка строк одинаковой длины
    
- Сортировка дат (год-месяц-день)
    

_MSD (Most Significant Digit)_ — вариант от старших разрядов к младшим, требует рекурсии, удобен для строк разной длины.
