#### **1. Основные задачи**

- **RMQ (Range Minimum Query)** — запрос минимума на отрезке.
    
    - **Вход**: Массив `A[0..n-1]`.
        
    - **Запрос**: `RMQ(l, r)`. Найти `min(A[l], A[l+1], ..., A[r])`.
        
- **RSQ (Range Sum Query)** — запрос суммы на отрезке.
    
    - **Вход**: Массив `A[0..n-1]`.
        
    - **Запрос**: `RSQ(l, r)`. Найти `A[l] + A[l+1] + ... + A[r]`.
        

---

#### **2. Классификация постановок**

Ключ к выбору алгоритма — ответить на два вопроса:

##### **A. По времени поступления запросов: Online vs Offline**

- **Online (онлайн)**: Запросы поступают **последовательно**. Ответ на запрос `i` должен быть выдан **до получения** запроса `i+1`. Алгоритм не знает будущего.
    
    - **Пример**: Интерактивная система, где пользователь задаёт вопросы в реальном времени.
        
    - **Требование к структуре**: Быстрый **ответ на один запрос** (`O(f(n))`), часто с предобработкой данных.
        
- **Offline (оффлайн)**: Все запросы `(l₁, r₁), (l₂, r₂), ...` известны **заранее**. Можно обрабатывать их в **любом порядке**, комбинировать, сортировать.
    
    - **Пример**: Пакетная обработка логов, анализ статического набора данных.
        
    - **Преимущество**: Часто можно применить **более эффективные алгоритмы** (сканирование, метод Мо), недоступные в online-режиме.
        

##### **B. По изменяемости массива: Static vs Dynamic**

- **Static (статический)**: Исходный массив **не изменяется** после построения структуры данных. Запросы — только чтение.
    
    - **Пример**: Поиск минимума в фиксированной выборке данных.
        
    - **Решение**: Часто допускает **тяжёлую предобработку** (O(n log n)) для **сверхбыстрых ответов** (O(1) для RMQ).
        
- **Dynamic (динамический, или с точками)**: Массив **можно изменять** — обновлять значения элементов (`A[i] = x`) между запросами.
    
    - **Пример**: Симулятор биржи, где цены акций обновляются, и нужно быстро считать минимум за период.
        
    - **Решение**: Нужны **структуры данных**, балансирующие скорость запроса и обновления (Дерево Фенвика, Дерево отрезков).


---

#### **3. Суть и сравнение основных структур данных (Online-Dynamic)**

- **Дерево Фенвика (Fenwick Tree / BIT)**:
    
    - **Суть**: Использует двоичное представление индексов для хранения частичных сумм.
        
    - **Плюсы**: Проще в коде, меньше константа, быстрее на практике для RSQ.
        
    - **Минусы**: Менее универсально (изначально — только RSQ, для RMQ — с ограничениями).
        
- **Дерево отрезков (Segment Tree)**:
    
    - **Суть**: Рекурсивно разбивает отрезок пополам, в вершинах хранит результат для своего подотрезка.
        
    - **Плюсы**: Чрезвычайно универсально. Легко модифицируется для **RMQ, RSQ, GCD, полиномов** и любых других **ассоциативных операций**. Поддерживает более сложные запросы (например, массовые обновления на отрезке с **отложенными операциями**).
        
    - **Минусы**: Больше кода, бóльшая константа, требует больше памяти.
        

---

### **Вывод для экзамена**

Чтобы выбрать решение для RMQ/RSQ, нужно **чётко определить постановку**:

1. **Меняется ли массив?** (Static → можно тяжёлая предобработка, Dynamic → нужна логарифмическая структура).
    
2. **Известны ли запросы заранее?** (Offline → можно сортировать и сканировать, Online → нужна структура с быстрым ответом).
    

**Итоговая таблица-шпаргалка:**

|Если вам нужно...|Выбирайте...|
|---|---|
|Статический массив, много запросов на минимум **онлайн**|**Sparse Table** (`O(1)` на запрос)|
|Статический массив, много запросов на сумму **онлайн**|**Префиксные суммы** (`O(1)` на запрос)|
|Динамический массив, нужна сумма **онлайн**|**Дерево Фенвика** (лучшая практическая скорость)|
|Динамический массив, нужен минимум или универсальность **онлайн**|**Дерево отрезков** (золотой стандарт)|
|**Оффлайн**-обработка любых запросов (особенно на статическом массиве)|**Метод Мо** или **сканирующая прямая** (часто `O((n+q)√n)`)|
