##### 2. Цель проекта (10-45с)
Целью нашего проекта является создание **облачного хранилища файлов на Java**, упрощённого аналога Google Drive или Яндекс.Диск.

Мы решаем 4 основные проблемы пользователей:

1. **Безопасность и контроль данных** — пользователь получает собственное защищённое пространство

2. **Упрощение совместной работы** — возможность управлять доступом к файлам и папкам для других пользователей

3. **Доступность файлов с любого устройства** — загрузил файл с ноутбука, открыл с телефона — всё работает через единое API

4. **Структурирование данных** — система папок, тегов и поиска помогает организовать даже большой объём файлов.

___
##### 3. Функциональные требования (45с-58с)
Перед нами стояли следующие требования:

Во-первых, **организация файлового пространства** — возможность загружать, скачивать и работать с директориями
Во-вторых, **система пользователей** — регистрация и аутентификация

(В презентации)
- Загружать и скачивать файлы

Здесь вы можете увидеть распределение задач между членами команды по спринтам.  В основном мы придерживались такому разделению: я отвечал за репозитории, Сергей — за контроллеры, Настя — за сервисы. ##### 6. High-level architecture (1м41с-2м2с)

На верхнем уровне архитектуры мы видим слой backend, который реализует всю бизнес-логику и предоставляет REST API клиентам, а также два хранилища — PostgreSQL для метаданных и пользователей и MinIO для файлов. Клиенты — например, Postman или будущий веб-интерфейс — взаимодействуют с системой только через REST API

___
##### 7. Стек технологий (2м2с-2м35с)
Для реализации архитектуры мы выбрали следующий стек:

1. Backend на **Java**
2. **MinIO** – как S3-совместимое хранилище для файлов. Его выбрали за простоту развёртывания и надёжность
3. **PostgreSQL** – работаем с ней через **JDBC**
4. **Netty** – для асинхронной обработки HTTP-запросов
5. **JWT** – для аутентификации и генерации токенов
6. **Docker**  – для контейнеризации и развёртывания
7. **TestContainers** – для интеграционных тестов с реальными БД и MinIO

___
##### 8. Схема БД (2м35с-2м56с)
Мы спроектировали базу данных из трёх основных таблиц: пользователи, файлы и refresh-токены. Файлы и токены привязаны к пользователю. 

Кроме того, файлы и папки хранятся в одной таблице — различаются флагом isDirectory. Хранить их вместе **проще для разработки** и **быстрее для запросов** — все операции над деревом папок делаются в одной таблице.

(В презентации схемка)
База данных состоит из трёх связанных таблиц:
1. Пользователи
2. Файлы 
3. Refresh-токены
Files и Refresh Tokens зависят от Users.
