### До

#### Валидация
1. Handler из Netty создаёт DTO и передает его контроллеру 
2. В контроллере есть дублирующий вызов .validate() с передачей туда JwtService (анти-паттерн, да) там, где нужна валидация токена; и сам вызов метода из сервиса

Проблемы такого подхода:
1. Дублирующий вызов .validate() в контроллере
2. Дублирующая логика валидации тех же полей
3. Сложные цепочки валидации с `Optional` полями:
4. Работа с сервисом для валидации токенов - нарушение SRP и инкапсуляции

#### Запросы-ответы

Постоянный парсинг входящих полей (из хедеров, HTTP body и headers), ручной маппинг DTO -> JSON

___

### После

#### 1. Архитектура pipeline

Перестраиваем цепочку обработки так, чтобы каждый этап решал ровно одну задачу.

- **JwtAuthenticationHandler:** Проверяет токен там, где он необходим. Если валиден — кладет `userId` в `AttributeKey` канала. Если нет — обрывает запрос.
    
- **RequestToDtoDecoder:** Определяет тип DTO по URL, вытаскивает данные из Header/Query/Body и создает объект. Кеширует классы DTO
    
- **GlobalValidationHandler:** Один на весь проект. Прогоняет созданный DTO через Hibernate Validator (аннотации).
    
- **Handler (вместо контроллеров):** Просто берет готовый DTO и `userId`, вызывает сервис и пишет результат в `ctx.writeAndFlush()`.
    
- **DtoToResponseEncoder:** Берет объект, смотрит его аннотации и рассовывает данные в Headers или Body ответа.

#### 2. Уровень DTO (Records + Annotations)

DTO теперь — это декларативное описание контракта.

- **Входящие DTO:** Используем аннотации у параметров конструктора:
    
    - `@QueryParam("name")`
        
    - `@RequestHeader("X-Token")`
        
    - `@RequestBody` (для JSON) - по умолчанию.
        
    - Стандартные аннотации валидации из Hibernate: `@NotBlank`, `@Positive`, `@Pattern`.
        
- **Исходящие DTO:**
    
    - `@ResponseHeader("Content-Type")` для полей, которые должны уйти в заголовки.

	- `@ResponseBody` (для JSON) - по умолчанию

#### 3. Reflection + Caching

Чтобы всё это не тормозило, реализуем механизм «инспекции» классов.

- **DtoMetadataCache:** Синглтон с `ConcurrentHashMap<Class<?>, DtoMetadata>`.
    
- **При первом обращении:** Рефлексией читаем конструктор рекорда, сохраняем «карту» (какой индекс аргумента откуда брать).
    
- **При последующих:** Просто дергаем конструктор с массивом объектов, собранных по карте.

##### 4. Удаление лишних слоев

- **Удаляем `FileController`:** Его задачи (парсинг параметров и вызов сервиса) теперь распределены между Декодером и Бизнес-хендлером.
    
- **Удаляем ручную валидацию:** Больше никаких `Validators.all(...)` и `if (!result.isValid())`. Всё происходит автоматически в пайплайне.
    
- **Удаляем передачу `JwtService` в DTO:** Токен проверяется один раз в начале пути.

```java
@Override
protected void encode(ChannelHandlerContext ctx, Object msg, List<Object> out) {
    // 1. Если это уже готовый низкоуровневый объект Netty - ничего не делаем, пускаем дальше
    if (msg instanceof ChunkedInput || msg instanceof ByteBuf || msg instanceof HttpContent) {
        out.add(ReferenceCountUtil.retain(msg));
        return;
    }

    // 2. Если это твой DTO (помечаем их интерфейсом или просто проверяем пакет)
    if (isYourDto(msg)) {
        FullHttpResponse response = assembleResponse(msg);
        out.add(response);
    } else {
        // 3. Если пришло что-то непонятное - просто кидаем дальше или логируем ошибку
        out.add(ReferenceCountUtil.retain(msg));
    }
}
```
