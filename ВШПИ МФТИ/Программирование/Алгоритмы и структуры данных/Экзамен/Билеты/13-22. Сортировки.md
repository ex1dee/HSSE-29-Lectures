### **1. Сортировки. Теорема о нижней границе времени сортировки. Стабильные сортировки**

**Сортировка** — процесс упорядочивания элементов последовательности по возрастанию (или убыванию).  
**Устойчивость (стабильность)** — свойство сортировки сохранять относительный порядок элементов с одинаковыми ключами.

**Пример устойчивости**:  
Исходный массив пар (ключ, значение):  
`(2, A), (1, B), (2, C)`  
После устойчивой сортировки по ключу:  
`(1, B), (2, A), (2, C)` — порядок (A, C) сохранён.  
После неустойчивой: возможен порядок `(1, B), (2, C), (2, A)`.

**Стабильные алгоритмы**:

- Сортировка вставками
    
- Сортировка слиянием
    
- Сортировка подсчётом (правильная реализация)
    
- LSD-сортировка
    

**Нестабильные алгоритмы**:

- Быстрая сортировка
    
- Пирамидальная сортировка
    
- Сортировка выбором
    

---

**Теорема о нижней границе времени сортировки сравнениями**:

Любая сортировка сравнениями требует Ω(n log n) сравнений в худшем случае.

**Доказательство**:

1. **Дерево решений**: Любой алгоритм сортировки сравнениями можно представить как бинарное дерево, где:
    
    - Каждый внутренний узел = сравнение двух элементов
        
    - Листья = возможные перестановки исходного массива
        
2. **Число листьев**: Для массива из n различных элементов существует n! возможных перестановок.  
    ⇒ Дерево должно иметь ≥ n! листьев.
    
3. **Высота дерева**: Бинарное дерево высоты h имеет ≤ 2ʰ листьев.  
    ⇒ `2ʰ ≥ n!`
    
4. **Логарифмируем**: `h ≥ log₂(n!)`
    
5. **Применяем формулу Стирлинга**: $n! \sim \sqrt{ 2\pi n }\left( \frac{n}{e} \right)^n$
	$\log_{2}(n!) \sim \log_{2}\left( \sqrt{ 2\pi n }\left( \frac{n}{e} \right) \right)^n = n\log_{2}n - n\log_{2}e +\frac{1}{2}\log_{2}(2\pi n)+o(1)$ 
6. **Итог**: `h ≥ Θ(n log n)` ⇒ Любая сортировка сравнениями требует
	`Ω(n log n)` сравнений.

### **2. Сортировка слиянием. Подсчёт числа инверсий**

**Сортировка слиянием (Merge Sort)**:

_Алгоритм_:

1. Рекурсивно разделяем массив на две половины
    
2. Сортируем каждую часть рекурсивно
    
3. Сливаем две отсортированные части в одну
    

_Слияние двух отсортированных массивов_:

1. Создаём пустой результат C размером |A| + |B|
    
2. Инициализируем три указателя:
    
    - `i = 0` (указывает на текущий элемент в A)
        
    - `j = 0` (указывает на текущий элемент в B)
        
    - `k = 0` (указывает на текущую позицию в C)
        
3. Пока оба указателя находятся в пределах своих массивов:
    
    - Сравниваем A[i] и B[j]
        
    - **Если A[i] ≤ B[j]**:
        
        - Копируем A[i] в C[k]
            
        - Увеличиваем i и k на 1
            
    - **Иначе**:
        
        - Копируем B[j] в C[k]
            
        - Увеличиваем j и k на 1
            
4. Копируем оставшиеся элементы из того массива, который ещё не обработан полностью
    
5. Возвращаем C

_Время работы_:  
T(n) = 2T(n/2) + O(n) ⇒ T(n) = O(n log n) (по мастер теореме о рекурсии)

_Память_: O(n) (требуется дополнительный массив для слияния)
_Стабильность_: Да, если при равенстве элементов брать из левой части

---

**Подсчёт числа инверсий**:

_Определение_: Инверсия — пара индексов (i, j), где i < j, но a[i] > a[j].

_Модификация сортировки слиянием для подсчёта инверсий_:

1. При рекурсивном вызове считаем инверсии в левой и правой частях
    
2. При слиянии: если элемент из правой части меньше текущего элемента из левой, то он образует инверсии со всеми оставшимися элементами левой части
    
3. Суммируем все три количества
    

_Пример_:

```text
Левый массив: [3, 5, 7] (уже отсортирован)
Правый массив: [2, 4, 6] (уже отсортирован)
При слиянии: 2 < 3 → образует инверсии с [3, 5, 7] → +3 инверсии
```

_Время работы_: O(n log n), так как это та же сортировка слиянием с дополнительным O(1) действий при каждом слиянии.

_Код (идея)_:

```python
def count_inversions(arr):
    if len(arr) <= 1:
        return arr, 0
    
    mid = len(arr) // 2
    left, inv_left = count_inversions(arr[:mid])
    right, inv_right = count_inversions(arr[mid:])
    
    merged = []
    i = j = 0
    inv_split = 0
    
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            inv_split += len(left) - i  # все оставшиеся в left больше right[j]
            j += 1
    
    merged.extend(left[i:])
    merged.extend(right[j:])
    
    return merged, inv_left + inv_right + inv_split

```

### **3. Бинарная пирамида (куча). Определение. Поддержка свойства пирамиды**

**Бинарная пирамида (куча)** — это полное бинарное дерево, удовлетворяющее свойству пирамиды:

- Для max-heap: значение в каждом узле ≥ значений в его потомках
    
- Для min-heap: значение в каждом узле ≤ значений в его потомках
    

**Представление в массиве** (0-индексация):

- Корень: индекс 0
    
- Для элемента с индексом i:
    
    - Левый потомок: 2i + 1
        
    - Правый потомок: 2i + 2
        
    - Родитель: $\left\lfloor \frac{i-1}{2} \right\rfloor$
    

**Полнота дерева**: все уровни, кроме последнего, полностью заполнены; последний уровень заполняется слева направо.

---

**Поддержка свойства пирамиды**:

1. **SiftUp (просеивание вверх)**:
    
    - Применяется, когда элемент может быть больше родителя (для max-heap)
        
    - Пока элемент больше родителя, меняем их местами
        
    - Поднимаемся к корню
        
```python 
    def sift_up(heap, idx):
        while idx > 0 and heap[idx] > heap[(idx-1)//2]:
            heap[idx], heap[(idx-1)//2] = heap[(idx-1)//2], heap[idx]
            idx = (idx-1)//2
	Время: O(log n)
```
2. **SiftDown (просеивание вниз)**:
    
    - Применяется, когда элемент может быть меньше одного из потомков
        
    - Пока элемент меньше какого-либо потомка, меняем с наибольшим потомком
        
    - Опускаемся до листьев
        
    
    ```python
    def sift_down(heap, idx, size):
        while 2*idx + 1 < size:
            left = 2*idx + 1
            right = 2*idx + 2
            largest = left
            
            if right < size and heap[right] > heap[left]:
                largest = right
            
            if heap[idx] >= heap[largest]:
                break
            
            heap[idx], heap[largest] = heap[largest], heap[idx]
            idx = largest
    ```
    
    ```
    Время: O(log n)
    ```

### **4. Бинарная пирамида. Основные операции. Heapify**

1. **Вставка элемента**:
    
    - Добавляем элемент в конец массива (на последнюю позицию последнего уровня)
        
    - Вызываем SiftUp для восстановления свойства пирамиды
        
    - Время: O(log n)
        
2. **Извлечение максимума (для max-heap)**:
    
    - Сохраняем значение корня
        
    - Перемещаем последний элемент в корень
        
    - Уменьшаем размер кучи
        
    - Вызываем SiftDown для корня
        
    - Возвращаем сохранённое значение
        
    - Время: O(log n)
        
3. **Увеличение/уменьшение ключа**:
    
    - Изменяем значение элемента
        
    - Если значение увеличилось → SiftUp
        
    - Если уменьшилось → SiftDown
        
    - Время: O(log n)
        
4. **Удаление произвольного элемента**:
    
    - Увеличиваем его ключ до ∞ (для max-heap)
        
    - Вызываем SiftUp, чтобы поднять элемент в корень
        
    - Извлекаем максимум
        
    - Время: O(log n)
        
5. **Построение кучи из массива (Heapify)**:
    
    - Вызываем SiftDown для всех элементов от $\left\lfloor  \frac{n}{2}  \right\rfloor$ до $0$ 
    (листы уже на своих местах)
        
    - Время: O(n)

### **5. Пирамидальная сортировка (Heap Sort)**:

_Алгоритм_:

1. Построить max-heap из исходного массива (Heapify)
    
2. Для i от n-1 до 1:
    
    - Поменять местами a[0] и a[i] (максимум уходит в конец)
        
    - Уменьшить размер кучи на 1
        
    - Вызвать SiftDown(0) для восстановления кучи
        

_Пример_:

```text
Исходный: [4, 10, 3, 5, 1]
Построили кучу: [10, 5, 3, 4, 1]
Шаг 1: [1, 5, 3, 4, 10], SiftDown → [5, 4, 3, 1, 10]
Шаг 2: [1, 4, 3, 5, 10], SiftDown → [4, 1, 3, 5, 10]
Шаг 3: [3, 1, 4, 5, 10], SiftDown → [3, 1, 4, 5, 10]
Шаг 4: [1, 3, 4, 5, 10] - отсортирован
```

_Характеристики_:

- Время работы: O(n log n) в худшем, среднем и лучшем случае
    
- Нестабильна
    
- Медленнее быстрой сортировки в среднем, но имеет гарантированную O(n log n)
    

_Оптимизация (Bottom-up Heap Sort)_:

- При SiftDown вместо сравнения с обоими детьми и родителем
    
- Идём только вниз до листа по пути больших детей, затем SiftUp
    
- Уменьшает количество сравнений на 20-30% (одно вместо двух в каждой итерации)
    

*Почему больших детей?*

Пусть мы идём по пути `p = [v₀, v₁, ..., vₖ]` (v₀ — корень, vₖ — лист).
На каждом шаге выбираем ребёнка с **большим** значением. Это значит:

```text
arr[v₀] ≥ arr[v₁] ≥ arr[v₂] ≥ ... ≥ arr[vₖ]
```

То есть путь **не возрастает**.

Если X должен занять какое-то место на этом пути, он должен встать **ниже всех элементов, которые больше него**.

**Только путь больших детей гарантирует**, что мы рассматриваем **минимально возможные значения** на каждом уровне, а значит, найдём **самое нижнее возможное место** для X.

### **6. Быстрая сортировка. Partition за O(1) доп. памятb

**Быстрая сортировка (Quick Sort)**:

_Основная идея_:

1. Выбрать опорный элемент (pivot)
    
2. Разделить массив на две части: ≤ pivot и > pivot
    
3. Рекурсивно отсортировать каждую часть
    

**Процедура Partition**:

1. **Разбиение Ломуто (Lomuto)**:
    ```python
    def partition_lomuto(arr, left, right):
        pivot = arr[right]  # выбираем последний элемент
        i = left  # граница для элементов ≤ pivot
        
        for j in range(left, right):
            if arr[j] <= pivot:
                arr[i], arr[j] = arr[j], arr[i]
                i += 1
        
        arr[i], arr[right] = arr[right], arr[i]
        return i
    ```
    
    - Инвариант: arr[left..i-1] ≤ pivot, arr[i..j-1] > pivot
        
    - Всегда делает n-1 сравнений
        
    - Медленнее на практике
        
2. **Разбиение Хоара (Hoare)** — предпочтительнее:
    ```python
    def partition_hoare(arr, left, right):
        pivot = arr[(left + right) // 2]  # лучше выбирать середину
        i = left - 1
        j = right + 1
        
        while True:
            i += 1
            while arr[i] < pivot:
                i += 1
            
            j -= 1
            while arr[j] > pivot:
                j -= 1
            
            if i >= j:
                return j
            
            arr[i], arr[j] = arr[j], arr[i]
    ```
    
    - Два указателя сходятся к центру
        
    - Меньше обменов в среднем
        
    - Возвращает границу, где левая часть ≤ pivot, правая ≥ pivot
	    
1. **Толстое разбиение** (Голландский флаг)
	```python
	def fat_partition(arr, left, right):
	    pivot = arr[(left + right) // 2]
	    low = left          # граница элементов < pivot
	    mid = left          # граница элементов = pivot
	    high = right        # граница элементов > pivot
	    
	    while mid <= high:
	        if arr[mid] < pivot:
	            arr[low], arr[mid] = arr[mid], arr[low]
	            low += 1
	            mid += 1
	        elif arr[mid] == pivot:
	            mid += 1
	        else:  # arr[mid] > pivot
	            arr[mid], arr[high] = arr[high], arr[mid]
	            high -= 1
	    
	    return low, high  # границы элементов = pivot
	```

	
	- **Три указателя**: `low`, `mid`, `high` делят массив на 4 зоны
	    
	- **Эффективно при повторяющихся элементах** — группирует равные pivot элементы
	    
	- **Три обменных операции** для трёх случаев (<, =, > pivot)
	    
	- **Возвращает два индекса** — начало и конец блока равных pivot элементов
	    
	- **Инвариант** (поддерживается на каждой итерации цикла `while mid <= high`):
		```text
		arr[left..low-1]  <  pivot   (синяя зона)
		arr[low..mid-1]   == pivot   (белая зона)  
		arr[mid..high]    ???        (неизвестная зона)
		arr[high+1..right] > pivot   (красная зона)
		```

При **случайном выборе pivot** (равновероятно любой элемент) матожидание времени работы QuickSort равно **O(n log n)**.

### **7. Поиск порядковой статистики. Оценка времени со случайным pivot**

**Порядковая статистика** — k-й по величине элемент в массиве (k от 1 до n).

**Алгоритм QuickSelect (аналог быстрой сортировки)**:

1. Выбрать случайный pivot
    
2. Выполнить Partition массива
    
3. Определить, в какой части находится k-й элемент:
    
    - Если pivot оказался на позиции k, вернуть его
        
    - Если k меньше индекса pivot, искать в левой части
        
    - Если k больше, искать в правой части
        

```python
def quickselect(arr, left, right, k):
    if left == right:
        return arr[left]
    
    pivot_index = partition(arr, left, right)
    
    if k == pivot_index:
        return arr[k]
    elif k < pivot_index:
        return quickselect(arr, left, pivot_index - 1, k)
    else:
        return quickselect(arr, pivot_index + 1, right, k)
```

При **случайном выборе pivot** матожидание времени поиска k-й порядковой статистики равно **O(n)**.

### **8. Алгоритм медианы медиан. Время поиска медианы медиан**

**Медиана медиан** — это способ выбора pivot, которая гарантирует хорошее разбиение массива. При её использовании в быстрой сортировке (QuickSort) мы получаем **детерминированный алгоритм с гарантией O(N log N) в худшем случае**. А при использовании в быстром выборе (QuickSelect) — алгоритм поиска k-й порядковой статистики с гарантией **O(n) в худшем случае**.»

**Алгоритм медианы медиан**:

1. Разделить массив на группы по 5 элементов
    
2. В каждой группе найти медиану (сортировкой за O(1), так как размер фиксирован)
    
3. Рекурсивно найти медиану найденных медиан
    
```python
def median_of_medians(arr, left, right):
    # 1. Базовый случай для маленьких массивов
    if right - left < 5:
        return sorted(arr[left:right+1])[(right - left) // 2]
    
    # 2. Разбиваем на группы по 5, находим медианы
    medians = []
    for i in range(left, right + 1, 5):
        group_end = min(i + 4, right)
        group_median = sorted(arr[i:group_end+1])[2]  # медиана группы из 5
        medians.append(group_median)
    
    # 3. Рекурсивно находим медиану медиан
    return median_of_medians(medians, 0, len(medians) - 1)
```

**Время поиска медианы медиан**:

_Ключевое свойство_: Медиана медиан гарантированно делит массив в соотношении не хуже чем 3/7.

_Доказательство_:

1. **Половина медиан ≥ M** (по определению медианы медиан)  
    → Не менее ⌈g/2⌉ групп, где медиана ≥ M,  
    где g = ⌈n/5⌉ — число групп.
2. **В каждой такой группе** хотя бы 3 элемента ≥ медианы группы (сама медиана + 2 больших элемента в группе)  
    → Эти 3 элемента ≥ M (т.к. медиана группы ≥ M).
3. **Итог**:  
    Число элементов ≥ M:  
    ≥ 3·⌈g/2⌉ ≥ 3n/10
    Т.е. ≥ 30% элементов ≥ M.
4. **Аналогично, ≥ 30% элементов $\leq$ M.**
5. **Тогда соотношение не хуже чем 3/7**

**Время работы:**

1. Разделение на группы и поиск в них медианы: O(n)
    
2. Рекурсивный поиск медианы медиан: T(n/5)
    
3. Partition: O(n)
    
4. Рекурсивный вызов для большей части: ≤ T(7n/10)
    

Рекуррентное соотношение:  
T(n) ≤ T(n/5) + T(7n/10) + O(n)

Докажем по индукции, что T(n) ≤ Cn. Пусть для m < n: T(m) ≤ Cm
Тогда $T(n) ≤ C\cdot n/5 + C\cdot 7n/10 + an = C \cdot \frac{9n}{10} + an$

Нужно: $C \cdot 9n/10 + an ≤ Cn ⇒ an ≤ Cn/10 ⇒ C ≥ 10a$

Таким образом, T(n) = O(n)

### **9. Сортировка подсчётом. Стабильный вариант**

_Условия_:

- Элементы — целые числа в диапазоне $[0, k)$, где k = O(n)
    
- Или вообще любой малый диапазон

_Нестабильный вариант_:

```python
def counting_sort_unstable(arr, k):
    count = [0] * k
    for x in arr:
        count[x] += 1
    
    result = []
    for i in range(k):
        result.extend([i] * count[i])
    
    return result
```

Время: O(n + k), Память: O(k)

---

**Стабильный вариант**:

_Алгоритм_:

1. Подсчитать количество каждого элемента
    
2. Вычислить префиксные суммы (позиции, где должны начинаться элементы)
    
3. Пройти исходный массив справа налево, размещая элементы по вычисленным позициям
    

```python
def counting_sort_stable(arr, k):
    n = len(arr)
    count = [0] * k
    
    # 1. Подсчет
    for x in arr:
        count[x] += 1
    
    # 2. Префиксные суммы (позиции)
    for i in range(1, k):
        count[i] += count[i-1]
    
    # 3. Размещение (справа налево для стабильности)
    result = [0] * n
    for i in range(n-1, -1, -1):
        x = arr[i]
        count[x] -= 1
        result[count[x]] = x
    
    return result
```

_Почему справа налево_: чтобы сохранить порядок одинаковых элементов.

_Характеристики_:

- Время: O(n + k)
    
- Память: O(n + k)
    
- Стабильна
    
- Не основана на сравнениях

## **10. Алгоритм LSD — поразрядная сортировка**:

_Идея_: сортировать числа по младшим разрядам к старшим, используя стабильную сортировку подсчётом для каждого разряда.    

_Алгоритм_:

```python
def lsd_sort(arr, d):  # d - количество разрядов
    n = len(arr)
    
    # Проходим по всем разрядам от младшего к старшему
    for digit in range(d):
        # Сортировка подсчетом по текущему разряду
        count = [0] * 10  # для цифр 0-9
        
        # Извлечение digit-й цифры
        for x in arr:
            digit_value = (x // (10**digit)) % 10
            count[digit_value] += 1
        
        # Префиксные суммы
        for i in range(1, 10):
            count[i] += count[i-1]
        
        # Размещение (справа налево)
        result = [0] * n
        for i in range(n-1, -1, -1):
            x = arr[i]
            digit_value = (x // (10**digit)) % 10
            count[digit_value] -= 1
            result[count[digit_value]] = x
        
        arr = result
    
    return arr
```

_Пример_:
```text
Исходно: [170, 45, 75, 90, 802, 24, 2, 66]
По 0-му разряду: [170, 090, 802, 002, 024, 045, 075, 066]
По 1-му разряду: [802, 002, 024, 045, 066, 170, 075, 090]
По 2-му разряду: [002, 024, 045, 066, 075, 090, 170, 802]
```

_Время работы_: O(d * (n + k)), где d — количество разрядов, k — основание системы счисления (10 для десятичной)

_Память_: O(n + k)

_Стабильность_: Да (используется стабильная сортировка подсчётом)

_Применение_:

- Сортировка целых чисел
    
- Сортировка строк одинаковой длины
    
- Сортировка дат (год-месяц-день)
    

**MSD (Most Significant Digit)** — вариант от старших разрядов к младшим, требует рекурсии, удобен для строк разной длины.

## **11. Квадратичные сортировки**

#### **A. Сортировка пузырьком (Bubble Sort)**

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n-1):
        swapped = False
        for j in range(n-1-i):
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
                swapped = True
        if not swapped:  # оптимизация: если не было обменов
            break
```

**Инвариант**: После i итераций последние i элементов отсортированы.  
**Оптимизации**:

1. Флаг `swapped` — досрочный выход
    
2. Уменьшение границы внутреннего цикла (`n-1-i`)
    

#### **B. Сортировка выбором (Selection Sort)**

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n-1):
        min_idx = i
        for j in range(i+1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
```

**Инвариант**: Первые i элементов — минимальные и отсортированы.  
**Почему нестабильна**:  
Пример: `[(2,'a'), (2,'b'), (1,'c')]`  
При обмене (1,'c') с (2,'a') порядок (2,'a') и (2,'b') нарушается.

#### **C. Сортировка вставками (Insertion Sort)**

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):  # i - первый неотсортированный
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j+1] = arr[j]  # сдвиг вправо
            j -= 1
        arr[j+1] = key  # вставка
```

**Инвариант**: Элементы arr[0..i-1] отсортированы.  
**Лучший случай O(n)**: если массив уже отсортирован (внутренний while не выполняется).

### **3. Сортировка Шелла (Shell Sort)**

#### **А. Основная идея**

- Улучшение сортировки вставками
    
- Сначала сортируем элементы, стоящие **далеко друг от друга**
    
- Постепенно уменьшаем шаг до 1
    
- **Идея**: далёкие инверсии убираются быстрее
    

#### **Б. Последовательности шагов**

1. **Оригинальная (Шелл)**: n/2, n/4, ..., 1 → **O(n²)**
    
2. **Хиббарда**: 1, 3, 7, 15, ... (2ᵏ-1) → **O(n^(3/2))**
    
3. **Кнута (рекомендуемая)**: 1, 4, 13, 40, ... (tₖ = 3·tₖ₋₁ + 1) → в худшем **O(n^(3/2))**, в среднем **O(n^(4/3))**
    
    - Начинаем с максимального шага < n/3
        
    - Делим на 3 на каждой итерации
        

#### **В. Реализация (последовательность Кнута)**

```python
def shell_sort(arr):
    n = len(arr)
    
    # 1. Вычисляем начальный шаг (последовательность Кнута)
    step = 1
    while step < n // 3:
        step = 3 * step + 1  # 1, 4, 13, 40, 121, ...
    
    # 2. Основной цикл с уменьшением шага
    while step >= 1:
        # Сортировка вставками с данным шагом
        for i in range(step, n):
            j = i
            temp = arr[i]
            # Сдвигаем элементы на расстоянии step
            while j >= step and arr[j - step] > temp:
                arr[j] = arr[j - step]
                j -= step
            arr[j] = temp
        
        step //= 3  # Уменьшаем шаг
```

#### **Г. Время работы**

- **Зависит от последовательности шагов**
    
- **На практике**: O(n^(4/3)) – O(n^(3/2))
    
- **Лучший случай**: O(n log n) (хорошая последовательность)
    
- **Худший случай**: O(n²) (плохая последовательность)
    

#### **Д. Преимущества**

1. **In-place**: O(1) доп. памяти
    
2. **Нестабильная** (из-за работы с разными шагами)
    
3. **Эффективнее квадратичных** на средних данных
    
4. **Простая реализация** на основе вставками
