#### В `Postgres` храним:
- **status**:
	- **PENDING** (начало любой операции, до изменения в Postgres)
	- **ERROR**
	- **READY**
	- **FATAL** (критические ошибки, слишком большое количество `retry`)
- **operation_type**
	*Не допускаем выполнение нескольких операций записи одновременно*
	*Операции чтения разрешены только при статусе `READY`*
	
	Только для операций записи:
	- **UPLOAD**
	- **DELETE**
	- **CHANGE_METADATA**
- **started_at**
	Время начала операции записи
- **updated_at**
	Время обновления – при каждом чанке или успешном шаге
- **retry_count** 
	Счётчик попыток `retry`
- **error_message**
	Причина `ERROR`
#### Фоновая очистка (раз в некоторое время)
- Долгий **PENDING**/Долгий **ERROR** + **UPLOAD** => удаление
- Долгий **PENDING**/**ERROR** + **DELETE** => `server-side retry`
	*Сразу после ошибки в **DELETE** делаем один `server-side retry`*
- Долгий **PENDING**/**ERROR** + **CHANGE_METADATA** => разблокировка файла 
	*Сразу после ошибки в **CHANGE_METADATA** делаем откат + `client-side retry`*

#### Retry
Если слишком много попыток, то помечаем запись как `FATAL` и пишем в логи критическую ошибку
