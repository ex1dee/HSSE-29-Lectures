#### **0. Матожидание**

Это **средневзвешенное значение случайной величины**, где весами служат вероятности соответствующих исходов.

**Формально:**  
Для случайной величины $ξ$, принимающей значения $x_{i}$​ с вероятностями $p_{i}$:

$$E[ξ] = \sum_{i} x_{i}p_{i}$$

**На простом примере:**  
Среднее значение выпадающего числа на идеальном кубике:
$$
E = 1 \cdot \frac{1}{6} + 2 \cdot \frac{1}{6} + \dots + 6 \cdot \frac{1}{6} = 3.5
$$
**Интуитивно:** Это то, чего можно ожидать «в среднем» при многократном повторении эксперимента.

#### **1. Хеш-функция**

- **Определение:** Это детерминированная функция `h: K -> {0, 1, ..., m-1}`, которая преобразует ключ (произвольного типа и размера: строка, объект, число) в целочисленный индекс (хеш) фиксированного диапазона `[0, m-1]`.
    
- **Требования:**
    
    - **Детерминированность:** Один и тот же ключ всегда должен давать один и тот же хеш.
        
    - **Быстрота вычисления:** Вычисление `h(k)` должно быть за `O(1)`.
        
    - **Равномерность:** Ключи должны распределяться по ячейкам максимально равномерно, чтобы минимизировать коллизии.
        

**Пример:** `h(k) = k mod m` (остаток от деления).

___

#### **2. Коллизия (Collision)**

- **Определение:** Ситуация, когда двум разным ключам `a` и `b` (`a ≠ b`) соответствует одно и то же значение хеш-функции: `h(a) = h(b)`.
    
- **Почему неизбежны:** По принципу Дирихле (правило "ящиков"): если количество ключей `n` больше размера таблицы `m` (`n > m`), то как минимум в одну ячейку попадет более одного ключа. Но коллизии могут возникать и при `n <= m` из-за неидеальности хеш-функции.
    
- **Решение:** Необходимы методы разрешения коллизий. Один из основных — **метод цепочек (chaining)**.
    

___

#### **3. Хеш-таблица на цепочках и основные операции**

- **Структура:** Массив `T` размера `m`, где каждая ячейка `T[i]` — это указатель на голову **связного списка**
    
- **Принцип:** Все ключи, чей хеш равен `i`, хранятся в одном списке (цепочке) в ячейке `T[i]`.
    

**Алгоритмы операций:**

1. **Вставка (Insert(key, value)):**
    
    - Вычислить хеш `j = h(key)`.
        
    - Вставить пару `(key, value)`. Если пара с таким ключом уже существует, заменить её значение на `value`
        
2. **Поиск (Find/Search(key)):**
    
    - Вычислить хеш `j = h(key)`.
        
    - Выполнить **линейный поиск** по связному списку в `T[j]`, сравнивая ключи.
        
3. **Удаление (Delete(key)):**
    
    - Вычислить хеш `j = h(key)`.
        
    - Найти узел в списке `T[j]` и удалить его из связного списка

**Сложность:**
- В худшем: O(n)
- В среднем: Θ(1+α) (про α ниже)

#### **4. Гипотеза простого равномерного хеширования**

Это **идеализированная математическая модель**, которая позволяет анализировать среднее поведение хеш-таблицы.

- **Формулировка:** Предполагается, что хеш-функция `h` распределяет **любой конкретный ключ** равновероятно и **независимо** от других ключей по всем `m` ячейкам таблицы.
    
    - **Равномерность:** Вероятность того, что ключ попадет в любую конкретную ячейку `h0`, равна `1/m`. `∀k ∈ K, ∀h0 ∈ [0, m-1]: P{h(k) = h0} = 1/m`.
        
    - **Независимость:** Хеши разных ключей не влияют друг на друга.
        
- **Важно:** Это сильное упрощение. На практике невозможно создать такую функцию, не зная распределения данных заранее. Однако **хорошие криптографические и не только хеш-функции (например, из семейства универсальных) приближаются к этому свойству в реальных задачах.**
    

___

#### **5. Математическое ожидание длины цепочки в предположении гипотезы**

- **Пусть:**
    
    - `n` — общее количество ключей в таблице.
        
    - `m` — размер таблицы (количество ячеек).
        
    - `α = n/m` — **коэффициент загрузки (load factor)**.
        
- **Утверждение:** При условии гипотезы простого равномерного хеширования **математическое ожидание длины любой цепочки** 
`E[length] = α`.
    
- **Доказательство:**
    
    1. Рассмотрим ячейку с индексом `h0`.
        
    2. Введем индикаторные случайные величины `X_p` для каждого ключа `k_p` (где `p = 1..n`):
        
        - `X_p = 1`, если `h(k_p) = h0`.
            
        - `X_p = 0` иначе.
            
    3. Длина цепочки в ячейке `h0` равна сумме всех индикаторов: `L = X_1 + X_2 + ... + X_n`.
        
    4. Найдем математическое ожидание `E[L]`, используя **линейность математического ожидания** (`E[ξ+η] = Eξ + Eη`):  
        `E[L] = E[∑ X_p] = ∑ E[X_p] = ∑ P{h(k_p) = h0}`
        
    5. По гипотезе равномерности: `P{h(k_p) = h0} = 1/m` для любого `p`.
        
    6. Итого: `E[L] = n * (1/m) = n/m = α`.
        

**Следствие:** Среднее время успешного поиска по таблице с цепочками пропорционально средней длине цепочки, то есть `Θ(1 + α)`. Если мы поддерживаем `α = O(1)` (например, `α < 2`), то **среднее время операций будет `O(1)`**.

___

#### **6. Динамическое расширение**
- На практике для поддержания `α = O(1)` и эффективности хеш-таблицу **динамически расширяют**. 
- Таким образом **вставка** выполняется за амортизированное O(1)
- **Алгоритм:**
  1. Задается **пороговый коэффициент загрузки** `threshold` (обычно 0.7–0.75).
  2. При превышении порога (`α > threshold`):
     - Выделяется новый массив большего размера (часто `m' = 2*m` или простое число).
     - **Перехеширование:** Для каждого элемента старой таблицы:
       - Вычисляется новый хеш `h'(k)` относительно нового размера `m'`.
       - Элемент вставляется в новую таблицу.
     - Старый массив освобождается.
