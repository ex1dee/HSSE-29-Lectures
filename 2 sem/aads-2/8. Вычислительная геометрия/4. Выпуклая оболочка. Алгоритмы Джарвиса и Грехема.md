> [!INFO] **Определение (Выпуклая оболочка)**
> 
> **Выпуклой оболочкой (Convex Hull)** множества точек $X$ называется минимальное выпуклое множество, содержащее $X$.
> 
> Интуитивно выпуклую оболочку можно представить как форму, которую примет растянутая канцелярская резинка, если её натянуть на все точки множества и отпустить. Вершинами оболочки станут крайние точки множества.

Всюду далее: $n$ — общее количество точек в исходном множестве, $h$ — количество точек, вошедших в итоговую выпуклую оболочку ($h \le n$).

## 1. Алгоритм Джарвиса (Jarvis March / "Заворачивание подарка")

### Зачем нужен алгоритм

Построение выпуклой оболочки плоского множества точек. Алгоритм является **чувствительным к выходу** (output-sensitive), то есть его скорость напрямую зависит от размера ответа ($h$).

### Суть и корректность алгоритма

Алгоритм работает по принципу шагания по крайним точкам:

1. **Поиск стартовой точки:** Находим самую левую точку множества (при равенстве координат $x$ — самую нижнюю). Обозначим её $p_1$. Она гарантированно входит в выпуклую оболочку.
    
2. **Поиск следующей вершины:** Находясь в текущей точке $p_i$, мы ищем такую точку $p_{i+1}$, которая является «самой правой» относительно всех остальных точек множества. Математически это означает, что для любой другой точки $q$ векторное (косое) произведение должно быть направлено в одну сторону:
    
    $$\vec{p_i p_{i+1}} \times \vec{p_i q} \ge 0$$
    
3. **Итерация:** Нашедшийся самый правый кандидат становится следующей вершиной оболочки. Повторяем шаг 2, пока не вернемся в стартовую точку $p_1$.
    

### Асимптотика

- **Временная сложность:** $\mathcal{O}(n \cdot h)$
    
    Нам нужно найти $h$ вершин оболочки. Для поиска каждой новой вершины мы перебираем все $n$ точек множества, чтобы найти точку с максимальным правым разворотом.
    
- **Пространственная сложность:** $\mathcal{O}(h)$ для хранения результата (или $\mathcal{O}(1)$, если модифицировать исходный массив).
    

> [!TIP] **Когда эффективен Джарвис?**
> 
> Алгоритм идеален, если точек в оболочке очень мало (например, $h = \mathcal{O}(1)$ или $h = \mathcal{O}(\log n)$). Тогда алгоритм работает практически за линейное время $\mathcal{O}(n)$. Однако в худшем случае (когда все точки лежат на окружности и $h = n$) асимптотика падает до $\mathcal{O}(n^2)$.

## 2. Алгоритм Грехема (Graham Scan)

### Зачем нужен алгоритм

Построение выпуклой оболочки. В отличие от Джарвиса, гарантирует стабильное время работы вне зависимости от формы оболочки.

### Суть и корректность алгоритма

Алгоритм Грехема использует метод сканирования (стековый обход) после предварительной сортировки:

1. **Базовая точка:** Находим самую нижнюю точку множества (при равенстве — самую левую). Обозначим её $p_0$.
    
2. **Полярная сортировка:** Сортируем все остальные точки по полярному углу относительно точки $p_0$ (в порядке возрастания угла, то есть против часовой стрелки). Если у каких-то точек углы совпадают, оставляем только самую удаленную от $p_0$.
    
3. **Обход (Скан):** Инициализируем стек, куда последовательно кладем $p_0$ и первую точку из отсортированного массива. Далее бежим по остальным точкам. Для каждой новой точки проверяем, образует ли она с двумя верхними точками в стеке **левый поворот** (поворот против часовой стрелки).
    
    - Пусть в топе стека лежат точки `next_to_top` и `top`, а рассматриваемая точка — `p`.
        
    - Если векторное произведение $\vec{\text{next\_to\_top} \to \text{top}} \times \vec{\text{top} \to p} > 0$, то поворот корректный (левый). Мы кладем $p$ в стек.
        
    - Если поворот правый или линии коллинеарны ($\le 0$), то точка `top` образует внутренний «впалый» угол. Мы удаляем `top` из стека (`pop`) и повторяем проверку для новой вершины стека.
        

### Пример кода (C++)

C++

```
#include <iostream>
#include <vector>
#include <algorithm>

struct Point {
    long long x, y;
};

Point p0; // Базовая точка

// Косое произведение векторов AB и BC
long long cross_product(Point a, Point b, Point c) {
    return (b.x - a.x) * (c.y - b.y) - (b.y - a.y) * (c.x - b.x);
}

// Квадрат расстояния между точками
long long dist_sq(Point a, Point b) {
    return (a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y);
}

// Компаратор для полярной сортировки
bool compare(Point a, Point b) {
    long long cp = cross_product(p0, a, b);
    if (cp == 0) {
        return dist_sq(p0, a) < dist_sq(p0, b);
    }
    return cp > 0; // Сортируем против часовой стрелки
}

std::vector<Point> convex_hull(std::vector<Point>& points) {
    int n = points.size();
    if (n < 3) return points;

    // 1. Находим самую нижнюю-левую точку
    int min_idx = 0;
    for (int i = 1; i < n; i++) {
        if (points[i].y < points[min_idx].y || 
           (points[i].y == points[min_idx].y && points[i].x < points[min_idx].x)) {
            min_idx = i;
        }
    }
    std::swap(points[0], points[min_idx]);
    p0 = points[0];

    // 2. Сортируем точки по полярному углу относительно p0
    std::sort(points.begin() + 1, points.end(), compare);

    // 3. Скан Грехема с использованием вектора как стека
    std::vector<Point> stack;
    stack.push_back(points[0]);
    stack.push_back(points[1]);
    stack.push_back(points[2]);

    for (int i = 3; i < n; i++) {
        while (stack.size() >= 2 && cross_product(stack[stack.size() - 2], stack.back(), points[i]) <= 0) {
            stack.pop_back(); // Удаляем точку, если поворот не левый
        }
        stack.push_back(points[i]);
    }
    return stack;
}
```

### Асимптотика

- **Временная сложность:** $\mathcal{O}(n \log n)$
    
    Основное время тратится на полярную сортировку точек — $\mathcal{O}(n \log n)$. Сам этап сканирования (обход циклом) работает за линейное время $\mathcal{O}(n)$, так как каждая точка кладется в стек ровно один раз и удаляется из него не более одного раза.
    
- **Пространственная сложность:** $\mathcal{O}(n)$ для хранения отсортированного массива и стека.
    

## Сравнение алгоритмов

|**Критерий**|**Алгоритм Джарвиса**|**Алгоритм Грехема**|
|---|---|---|
|**Худшее время**|$\mathcal{O}(n^2)$|$\mathcal{O}(n \log n)$|
|**Лучшее время**|$\mathcal{O}(n)$ (если $h$ константа)|$\mathcal{O}(n \log n)$|
|**Зависимость от ответа**|Да (Output-sensitive)|Нет|
|**Сложность реализации**|Очень простая|Средняя (требует аккуратной полярной сортировки)|
