## **Списки, Стек, Очередь, Дек**

### **1. Односвязный список (Singly Linked List)**

**Структура:** Узлы, каждый содержит:

- `value` — данные
- `next` — указатель на следующий узел (или `nullptr` для конца)

**Операции:**

- `InsertAfter(prev_node, value)`: O(1) — создали узел, перенаправили указатели
- `EraseAfter(prev_node)`: O(1) — перекинули указатель через узел
- `Find(value)`: O(n) — нужно пройтись по списку
- **Главная проблема:** Нет быстрого доступа по индексу, нельзя эффективно удалить текущий узел, зная только его (нужен указатель на предыдущий)
### **2. Двусвязный список (Doubly Linked List)**

**Структура:** Узлы содержат:

- `value`
- `next` — на следующий
- `prev` — на предыдущий

**Преимущества:**

- Можно удалять узел по указателю на него за O(1) (так как знаем предыдущий через `prev`)
- Можно итерировать в обе стороны
- **Стандартная реализация** `std::list` в C++, `list` в Python (на самом деле CPython list — динамический массив)

**Недостатки:** Больше памяти (2 указателя вместо 1).

---

### **3. Стек (LIFO — Last In First Out)**

**Интерфейс:**

- `push(x)` — добавить наверх
- `pop()` — снять сверху (и вернуть)
- `top()` — посмотреть верхний
- `empty()`, `size()`

**Реализации:**

1. **Через список (односвязный):**
    - `push` = добавить в голову O(1)
    - `pop` = удалить из головы O(1)
    - Минимум памяти, но есть накладные расходы на указатели
2. **Через динамический массив (вектор):**
    - `push` = `push_back` O(1) амортизированно
    - `pop` = `pop_back` O(1)
    - **Лучше на практике** из-за локальности данных.

---

### **4. Очередь (FIFO — First In First Out)**

**Интерфейс:**

- `enqueue(x)` или `push(x)` — в конец
- `dequeue()` или `pop()` — из начала
- `front()` — первый элемент
- `empty()`, `size()`

**Реализации:**

1. **Через двусвязный список:**
    
    - `push_back` + `pop_front` оба O(1)
        
    - Но много памяти на указатели
        
2. **Кольцевой буфер — оптимально:**
    
    - **Структура:** Массив фиксированного размера `capacity`, два индекса:
        
        - `head` (или `front`) — откуда забираем
            
        - `tail` (или `back`) — куда добавляем (указывает на следующую свободную ячейку)
            
    - **Логика:**
        
        ```cpp
        enqueue(x):
            if size == capacity: расширить или ошибка
            buffer[tail] = x
            tail = (tail + 1) % capacity
            size++
        
        dequeue():
            if empty(): ошибка
            x = buffer[head]
            head = (head + 1) % capacity
            size--
            return x
        ```
    - **Преимущества:**
        
        - O(1) на операции
        - Отличная локальность данных (все в массиве)
        - Минимум памяти (только массив + 2 индекса + size)

---

### **5. Дек (Deque — Double Ended Queue)**

**Интерфейс:** Очередь, но можно добавлять/удалять с двух концов:

- `push_front(x)`, `push_back(x)`
    
- `pop_front()`, `pop_back()`
    
- `front()`, `back()`
    

**Реализации:**

1. **Через двусвязный список:**
    
    - Все 4 основные операции за O(1)
        
    - Но много памяти
        
2. **Через кольцевой буфер (расширенный):**
    
    - Теперь `head` и `tail` могут двигаться в обе стороны:
        
        ```cpp
        push_front(x):
            head = (head - 1 + capacity) % capacity  // двигаем назад
            buffer[head] = x
            size++
        
        push_back(x):  // как enqueue
            buffer[tail] = x
            tail = (tail + 1) % capacity
            size++
        ```
        
    - **Проблема:** При `push_front` может "догнать" `tail`. Нужно либо расширять, либо изначально размещать в центре массива.
        
    - **Стандартная реализация (`std::deque`):** Массив указателей на блоки (например, по 512 элементов). Каждый блок — массив. Позволяет O(1) вставку в оба конца без дорогого расширения всего массива.

### 6. Циклический буфер со стиранием

**Циклобуфер (кольцевой буфер)** — массив фиксированного размера, работающий по принципу «запись поверх старого».

#### **Суть**

- **Фиксированный размер** `capacity`
- **Два указателя:**
    - `head` — на самый старый элемент

    - `tail` — на место для новой записи
        
- **При переполнении** (`tail` догоняет `head`) — `head` сдвигается, **старый элемент теряется**
    
- **Не является очередью** — это **буфер последних N элементов**

#### **Основные формулы**

```python
push(x):
  buffer[tail] = x
  tail = (tail + 1) % capacity
  
  if size < capacity:
      size++
  else:
      head = (head + 1) % capacity  # потеря старого

pop():
  if size == 0: ошибка
  x = buffer[head]
  head = (head + 1) % capacity
  size--
  return x
```

#### **Пример (capacity=3)**

``` python
1. push(A): [A,_,_] h=0,t=1,size=1
2. push(B): [A,B,_] h=0,t=2,size=2
3. push(C): [A,B,C] h=0,t=0,size=3 ← полон
4. push(D): [D,B,C] h=1,t=1,size=3 ← A потерян!
5. pop() → B: [D,_,C] h=2,t=1,size=2
```

## **12. Очередь с поддержкой ассоциативноей операции (например, минимума)**

### **Зачем это нужно?**

Обычная очередь умеет:

- `push(x)` - добавить в конец
    
- `pop()` - удалить из начала
    
- `front()` - посмотреть первый
    

**Хотим добавить**: `get_min()` - найти **минимальный элемент во всей очереди** за O(1).
### ***Два специальных стека**

Идея: очередь = `стек_out` (голова) + `стек_in` (хвост)

**Но не простые стеки!** Каждый стек хранит **две вещи**:

1. Сам элемент
    
2. **Минимум во всём стеке снизу до этого элемента**
    

```text
Пример стека in:
Значения:  [5, 3, 7]
Минимумы:  [5, 3, 3]  ← min(5)=5, min(5,3)=3, min(5,3,7)=3
```
### **Как работает очередь?**

**Правила**:

1. `push(x)` → просто кладём в `стек_in` с обновлением минимума
2. `pop()` → если `стек_out` пуст, перекладываем **всё** из `in` в `out`
3. `get_min()` → `min(минимум_in, минимум_out)`

### **Пример по шагам**

```text
1. push(5) → in: [5(мин=5)], out: []
   get_min() = min(5, ∞) = 5

2. push(3) → in: [5(5), 3(3)], out: []
   get_min() = min(3, ∞) = 3  ← минимум обновился!

3. push(7) → in: [5(5), 3(3), 7(3)], out: []
   get_min() = min(3, ∞) = 3

4. pop() → out пуст, перекладываем всё из in в out:
   out станет: [7(7), 3(3), 5(5)]  ← элементы перевернулись!
   in станет: []
   Удаляем из out → возвращаем 5
   get_min() = min(∞, 3) = 3  ← минимум остался верный!

5. push(2) → in: [2(2)], out: [7(7), 3(3)]
   get_min() = min(2, 3) = 2
```
### **Почему это быстро?**

- `push`: O(1) — просто кладём в стек
``` text
push(x) в стек:
  if стек пуст: 
    кладём (x, x)
  else:
    prev_min = минимум предыдущего элемента
    new_min = min(x, prev_min)
    кладём (x, new_min)


Минимум всего стека = минимум у верхнего элемента
```
- `pop`: **амортизированно** O(1)  
    (редкое перекладывание O(n) компенсируется многими простыми O(1))
    
- `get_min`: O(1) — просто смотрим два числа
    

### **А если нужна не min, а другая операция?**

Работает для **любой ассоциативной** операции:

- `max` — максимум в очереди
    
- `sum` — сумма всех элементов
    
- `xor` — XOR всех элементов
    
- `gcd` — НОД всех элементов
    

**Ассоциативность** = можно группировать как угодно:  
`(a+b)+c = a+(b+c)` — для суммы работает  
`min(min(a,b),c) = min(a,min(b,c))` — для минимума работает
