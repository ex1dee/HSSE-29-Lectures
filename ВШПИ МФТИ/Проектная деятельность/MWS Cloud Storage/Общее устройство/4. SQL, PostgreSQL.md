##### SQL (Strucrured Query Language)
Это **декларативный** язык программирования, применяемый для создания, модификации и **управления данными** в **реляционной** базе данных, управляемой соответствующей системой управления базами данных.

###### Декларативный язык

| Декларативный язык                               | Императивный язык                                               |
| ------------------------------------------------ | --------------------------------------------------------------- |
| Описание того, **"что"** хотим получить.         | Описание того, **"как"** достичь результата                     |
| Можно делать только то, для чего язык создавался | Можно лучше оперировать машинными ресурсами на "низовом" уровне |
| **Примеры:** HTML, SQL                           | **Примеры:** C, C++, C#, Go, Java, Python...                    |

##### Реляционные базы данных

Такие базы данных (БД) состоят из связанных таблиц. 
SQL - стандарт работы с реляционными БД, универсальный по своим возможностям, но имеющий множество диалектов.
В SQL-ориентированных БД класс объектов (например, "Документы" с атрибутами "Номер" и "Дата") представлен отдельной таблицей.

Атрибуты представлены столбцами, экземпляры объектов - строками, а на пересечении (в поле конкретной строки) хранится значение данного атрибута для конкретного экземпляра (например, Номер=123, Дата=01.01.2000).
Поэтому все строки одной таблицы имеют один и тот же формат (в отличие от нереляционных БД).

Между собой таблицы связываются какими-то отношениями, которые определяются ключами.
Как правило, у любой таблицы есть **первичный ключ (Primary Key, PK)**, и он необходим, чтобы уникально идентифицировать любую из строк этой таблицы.

 *По некоторым причинам первичного ключа может не быть (например, очень частая запись логов, при которой идентификация по секудам не подходит). Тогда в качестве первичного используют суррогатный ключ или вообще его не делают, если отдельные записи отдельно идентифицировать не нужно, и на таблицу никто не ссылается.*

Первичные ключи используются именно для того, чтобы можно было сослаться на конкретную запись или провзаимодействовать с ней. А для того, чтобы "сослаться" со стороны подчинённой таблицы используются **внешние ключи (Foreign Keys, FK)** - они определяют по соответствию значений каких полей в дочерней и родительской таблице устанавливается связь.

Внешний ключ может ссылаться не только на первичный, но и на любой **уникальный ключ (Unique Key)**, которых на таблице может быть несколько (в отличие от первичного).

##### PostgreSQL
Имеет клиент-серверную архитектуру. Клиент отправляет запрос (как правило, текстовый, с SQL-командами) и получает в ответ некоторый код результата и, возможно, выборку.
Для того, чтобы можно было послать это серверу, нужно клиентское приложение или библиотека для приложения.

###### Общение с PostgreSQL-базой
- **psql.** Консольный клиент, входит в состав стандартного дистрибутива PostgreSQL-сервера.
- **Десятки утилит с графическим интерфейсом.**

##### Базовые SQL-команды

`SELECT` - Получить выборку записей

`CREATE` - Создать объект СУБД
`ALTER` - Изменить объект СУБД
`DROP` - Удалить объект СУБД

`INSERT` - Вставить записи таблицы
`UPDATE` - Изменить записи таблицы
`DELETE/TRUNCATE` - Удалить записи таблицы

##### Синтаксис PostgreSQL

```
-- это однострочный комментарий
/* а это -
	- многострочный */
	  fld      -- это поле/столбец
	  Fld      -- это то же самое поле
	  FLD      -- ... и это – все оно же (приводится к lower case)
	  "Fld"    -- а вот это – тоже поле, но совсем другое (кавычки дают регистрозависимость)
	  'str'    -- это строка
	  
	  'st''r'  -- это строка с одинарным апострофом
	  E'st\'r' -- ... и это – она же
	  $$st'r$$ -- ... и даже вот это
	  $abcd$st'r$abcd$
```

Поля регистронезависимы (автоматически приводятся к нижнему регистру). Для сохранения регистра и "странных" имён (например, с пробелом, по-русски, по-китайски) используются двойные кавычки

###### Базовые типы данных
**Числовые типы.** 2-, 4-, 8-байтные целочисленные, 4- и 8-байтовые с переменной точностью (с плавающей точкой) и `numeric/decimal` с указанной точностью (хранятся посимвольно).
`numeric` стоит использовать там, где ошибка в округлении недопустима.
**`Serial`-псевдотипы.** Позволяют определить поля с автоматически формируемым возрастающим значением "по умолчанию": `1, 2, 3, ...`
**Символьные типы.** `char/varchar` (из стандарта SQL), `text` (строка неограниченной переменной длины), `bpchar` (строка неограниченной переменной длины с удалением пробелов) (PostgreSQL-специфичные типы).
**Дата и время.** Хранятся как целочисленные, отсичтываются от `POSTGRES_EPOCH` (01.01.2000) в соответствующих единицах (сутках или микросекундах).
**Логический тип.** `boolean`, принимает значения TRUE/FALSE или NULL (любой тип данных в SQL может принимать значение NULL) 
**И другие (в том числе, свои собственные)...**

###### INSERT
Указываем, в какую таблицу и в какие поля должны быть добавлены данные. Значения позиционно соответствуют указанным полям таблицы.

```
INSERT INTO tbl(      -- куда будем вставлять данные  
k                   -- имена полей
, v
)VALUES                -- перечисляем вставляемые строки  
(1, '1st string')
, (102, 'another string')
, (3, NULL);          -- вовсе не ''
```

###### UPDATE
Указываем, в какой таблице и как хотим изменить поля.
Можно менять сразу несколько полей.
И, дополнительно, описываем условие, которое должно отобрать только те строки, для которых наша операция должна отработать. В данном случае мы для строки с `k = 102` (обратите внимание на одинарное равенство при сравнении) хотим изменить строковое значение `v` на новое, а из значения `k` вычесть 100 (присвоение точно так же описывается одинарным символом равенства).

```
UPDATE  
tbl
SET
  k = k - 100      -- правила изменения значений полей
  , v = '2nd string'
  WHERE
    k = 102;         -- условие отбора строк
```

 ###### **DELETE**
Указываем, какой элемент хотим удалить.

```
DELETE FROM
  tbl
  WHERE
    v IS NULL;
```

С `NULL`-значениями нельзя пользоваться обычными операторами типа "равно"/"не равно", для них есть свои операторы `IS`. В данном случае, мы используем `IS NULL`, чтобы проверить на совпадение с `NULL`-значением.

###### NULL-логика
Базовые операторы (`=, <>, NOT`) выдают значение `NULL`, если его имеет хотя бы один из аргументов. А при приведении типов в условии оно превращается в "ложь", и ни одну запись вы не отберете.

Поэтому для сравнений `NULL` и с ним (в конкретном поле или для всей строки сразу) стоит использовать операторы `IS/IS NOT` или `IS DISTINCT FROM/IS NOT DISTINCT FROM`. Некоторые вещи не всегда очевидны, поэтому [вот шпаргалка](https://habr.com/ru/post/491366/), которой можно пользоваться.

###### RETURNING

Нужна, если мы хотели не просто удалить записи, но и узнать, какие именно были удалены.

Чтобы СУБД ответила нам не просто "_я вставила/обновила/удалила две строки_", а "_я обработала две вот такие строки_", необходимо воспользоваться ключевым словом `RETURNING` и перечислить те поля, которые мы хотим увидеть:

```
DELETE FROM
  tbl
  WHERE
    v IS NULL
    RETURNING *;
```

Здесь мы используем "`*`", которая в SQL означает "все поля". В данном случае мы увидим, что удаляется одна строка со значением 3 в поле `k`:

```
   k    |  v
integer | text
      3 |
```


###### SELECT

Нужна чтобы что-то взять из БД, выбрав из таблицы какие-то записи.

Воспользуемся командой [SELECT](https://postgrespro.ru/docs/postgresql/16/sql-select),  указав "`*`" вместо списка полей:

```
SELECT
  *
FROM
	tbl;
```

И увидим то, что осталось в таблице после всех наших манипуляций:

```
   k    |  v
integer | text
      1 | 1st string
      2 | 2nd string
```

Видим две строки, которые соответствуют тому условию, которое мы задали для выборки.
