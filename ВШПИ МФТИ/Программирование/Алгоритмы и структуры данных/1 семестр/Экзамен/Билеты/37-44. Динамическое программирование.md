## **1. Наибольшая возрастающая подпоследовательность (LIS)**

### **Что нужно найти:**

**Длину самой длинной строго возрастающей подпоследовательности** в массиве `a[0..n-1]`.

**Уточнение:**

- **Подпоследовательность** — элементы идут в исходном порядке, но не обязательно подряд

### **1. Квадратичное решение O(n²)**

#### **Идея состояния:**

`dp[i]` = длина НВП, которая **обязательно заканчивается в `a[i]`**.

#### **Переход:**

```text
dp[i] = 1 + max(dp[j]) для всех j < i, где a[j] < a[i]
```

**Почему такой переход?**  
Мы смотрим на все предыдущие позиции `j`. Если `a[j] < a[i]`, значит элемент `a[j]` **может стоять прямо перед `a[i]`** в возрастающей подпоследовательности. Тогда:

- Берём лучшую длину для `j` (это `dp[j]`)
    
- Добавляем наш элемент `a[i]` (+1)
    
- Выбираем максимальную длину среди всех возможных `j`
    
**Базовый случай:**  
`dp[i] = 1` — подпоследовательность из одного элемента всегда существует.

#### **Ответ:** `max(dp)`

### **2. Решение за O(n log n)**

#### **Идея:**

Массив `tails[len]` = **минимальный возможный последний элемент** среди всех НВП длины `len+1`.

**Интуиция:**  
Представьте, что у нас есть несколько "кандидатов" на концы подпоследовательностей разной длины. Для фиксированной длины `L` нам выгодно хранить **самый маленький** возможный конец — так у будущих элементов больше шансов "прицепиться".

#### **Алгоритм:**

Для каждого нового элемента `x`:

1. Бинпоиском ищем первую позицию в `tails`, где `tails[pos] ≥ x`
    
2. Если нашли — заменяем `tails[pos] = x`
    
3. Если не нашли — добавляем `x` в конец
    

**Почему это работает?**

- `tails` отсортирован по построению
    
- Заменяя `tails[pos]` на `x`, мы **не уменьшаем длину** НВП, но **улучшаем её потенциал** для будущих элементов
    
- Добавляя в конец — действительно нашли более длинную подпоследовательность

#### **Ответ:** `len(tails)`

## **2. Наибольшая общая подпоследовательность (LCS)**

### **Что нужно найти:**

Длину самой длинной подпоследовательности, которая есть и в строке A, и в строке B.

### **Идея состояния:**

`dp[i][j]` = длина LCS для **префиксов** `A[0..i-1]` и `B[0..j-1]`.

**Почему префиксы?**  
LCS — задача о согласовании двух последовательностей. Естественно смотреть "сколько мы уже согласовали" от начала каждой последовательности.

#### **Переход:**

```text
if A[i-1] == B[j-1]:
    dp[i][j] = dp[i-1][j-1] + 1
else:
    dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

**Почему так?** Рассмотрим последние символы `A[i-1]` и `B[j-1]`:

**Случай 1: Они равны**  
Тогда они **обязательно входят** в LCS (можно доказать от противного). Значит:

- Берем LCS для префиксов без этих символов (`dp[i-1][j-1]`)
    
- Добавляем этот общий символ (+1)
    

**Случай 2: Они разные**  
Тогда **хотя бы один из них не входит** в LCS. У нас есть две возможности:

- `A[i-1]` не входит → смотрим `dp[i-1][j]`
    
- `B[j-1]` не входит → смотрим `dp[i][j-1]`
    

Берём максимум, потому что хотим **наибольшую** подпоследовательность.

#### Ответ: `dp[n-1][n-1]`

##  **3. Задача о рюкзаке за O(nW)**

### **Что нужно найти:**

**Максимальную суммарную стоимость предметов**, которые можно уложить в рюкзак вместимостью `W`.

**Дано:**

- `n` предметов
    
- Вес `w[i]` и стоимость `c[i]` для каждого предмета
    
- Вместимость рюкзака `W`
    

**Ограничения:**

- Каждый предмет можно взять **не более 1 раза**
    
- Суммарный вес ≤ `W`

### **Идея состояния:**

`dp[w]` = максимальная стоимость, которую можно набрать **с общим весом ровно w**.

#### **Переход:**

```text
dp[j] = max(dp[j], dp[j - w[i]] + c[i])
```

**Почему такой переход?**  
Для предмета `i` с весом `w[i]` и стоимостью `c[i]`:

**Вариант А: Не берём предмет**  
Тогда стоимость остаётся прежней: `dp[j]` (уже посчитанное для предыдущих предметов)

**Вариант Б: Берём предмет**  
Тогда:

- Вес до взятия предмета должен быть `j - w[i]` (чтобы после добавления стало `j`)
    
- Стоимость до взятия: `dp[j - w[i]]`
    
- После взятия: `dp[j - w[i]] + c[i]`
    

#### Псевдокод
``` python
n = len(w)
dp = [0] * (W + 1)

for i in range(n):
	wi = w[i]
	ci = c[i]
	
	for j in range(W, wi - 1, -1):
		dp[j] = max(dp[j], dp[j - wi] + ci)

return dp[W]
```

**Почему идём с конца?**  
Если идти с начала, то предмет `i` может быть взят **несколько раз** (получится рюкзак с повторениями). При движении с конца мы гарантируем, что `dp[j - w[i]]` ещё не учитывает текущий предмет.

#### Ответ: `dp[w]`

## **4. Оптимальное перемножение матриц за O(n³)**

### **Что нужно найти:**

**Минимальное количество умножений** для перемножения цепочки матриц в оптимальном порядке.

**Дано:**

- Размеры матриц: `p[0..n]`
    
- Матрица `i` имеет размер `p[i-1] × p[i]`
    

**Уточнение:**

- Умножать можно только если количество столбцов первой равно количеству строк второй
    
- Количество операций (умножений элементов) для умножения матриц `(m×n)` на `(n×k)` = `m·n·k`
    
- Найти **порядок расстановки скобок**, минимизирующий общее количество операций
    

**Пример:**  
`p = [10, 30, 5, 60]` (3 матрицы: 10×30, 30×5, 5×60)  
Оптимально: `(A×(B×C))` = 10×30×60 + 30×5×60 = 1800 + 9000 = 10800 операций  
**Ответ:** `10800`
### **Идея состояния:**

`dp[i][j]` = минимальное число операций для перемножения матриц с `i`-й по `j`-ю.

**Почему по отрезкам?**  
Умножение матриц ассоциативно: `(A×B)×C = A×(B×C)`. Нам нужно найти оптимальную **расстановку скобок** в цепочке умножений. Естественно рассматривать подцепочки.

#### **Переход:**

```text
dp[i][j] = min(
    dp[i][k] + dp[k+1][j] + p[i]*p[k+1]*p[j+1]
) для всех k от i до j-1
```

**Почему именно так?**  
Разбиваем цепочку `[i..j]` на две части: `[i..k]` и `[k+1..j]`. Сначала оптимально перемножаем левую часть, потом правую, потом перемножаем результаты.

**Откуда `p[i-1]*p[k]*p[j]`?**

- Левая часть даёт матрицу размера `p[i-1] × p[k]`
    
- Правая часть даёт матрицу размера `p[k] × p[j]`
    
- Умножение этих двух матриц требует `p[i-1]*p[k]*p[j]` операций
    

**Почему перебираем `k`?**  
Потому что мы не знаем, где ставить "верхний уровень" скобок. Перебираем все возможные точки разбиения.

#### **Псевдокод:**
```python
n = len(p) - 1
dp = [[0] * n for _ in range(n)]

# length - длина подцепочки (количество матриц в ней)
for length in range(2, n + 1):  # length от 2 до n
	for i in range(0, n - length + 1):
		j = i + length - 1 
		dp[i][j] = float('inf')
		
		for k in range(i, j):
			cost = dp[i][k] + dp[k+1][j] + p[i] * p[k+1] * p[j+1]
			
			if cost < dp[i][j]:
				dp[i][j] = cost

return dp[0][n-1]
```

**Почему заполняем по возрастанию длины?**  
Потому что для вычисления `dp[i][j]` нам нужны `dp[i][k]` и `dp[k+1][j]`, которые короче. Классический случай ДП по подотрезкам.

#### **Ответ:** `dp[0][n-1]`

## **5. k-й член однородной линейной рекурренты за O(n³ log k)**

### **Идея**

Линейная рекуррента `n`-го порядка:

```text
F(k) = a₁·F(k-1) + a₂·F(k-2) + ... + aₙ·F(k-n)
```

**Проблема:** Наивно считать обычным ДП за O(n·k) — долго при больших k.

#### **Матричная форма:**

```text
| F(k)    |   | a₁ a₂... aₙ₋₁ aₙ |   | F(k-1) |
| F(k-1)  |   | 1  0 ... 0    0 |   | F(k-2) |
| ...     | = | 0  1 ... 0    0 | × | ...    |
| F(k-n+1)|   | 0  0 ... 1    0 |   | F(k-n) |
```

**Почему именно такая матрица?**  
Первая строка — коэффициенты рекурренты. Остальные строки — просто сдвиг: `F(k-1)` становится `F(k-2)` и т.д.

#### **Переход:**

```text
Вектор_состояния(k) = M × Вектор_состояния(k-1)
```

Тогда:

```text
Вектор_состояния(k) = M^(k-(n-1)) × Вектор_состояния(n-1)
```

**Почему сложность O(n³ log k)?**

- Умножение матриц n×n: O(n³)
    
- Бинарное возведение в степень: O(log k) умножений
    
- Итого: O(n³ log k)

## **6. Рюкзак за O(n·2ⁿ)**

### **Идея:**

Перебираем **все подмножества** предметов.

**Почему 2ⁿ?**  
У каждого из `n` предметов 2 состояния: взят или не взят. Всего комбинаций: 2·2·...·2 = 2ⁿ.

#### **Перебор:**

```python
for mask from 0 to (1<<n)-1: # Перебираем все 2^n возможных масок
    weight = 0
    cost = 0
    for i from 0 to n-1:
        if mask & (1<<i): # Если маска содержит i-й предмет
            weight += w[i]
            cost += c[i]
    if weight <= W:
        answer = max(answer, cost)
```

**Когда применяется?**
Когда `n ≤ 20`, при этом `W` может быть большим, то это быстрее, чем `O(nW)`

## **7. Гамильтонов путь (TSP)**

### **Идея состояния:**

`dp[mask][v]` = минимальная длина пути, который:

- Посетил все вершины из `mask`
    
- Заканчивается в `v`
    

#### **Переход:**

```text
dp[mask][v] = min(
    dp[mask_without_v][u] + dist[u][v]
) для всех u, содержащихся в mask_without_v и имеющих ребро u->v

mask_without_v = mask ^ (1 << v)
```

**Почему такой переход?**  
Чтобы попасть в состояние `(mask, v)`, мы должны:

1. Прийти из какой-то вершины `u`
    
2. Причём `u` уже была в маршруте (`u ∈ mask_without_v`)
    
3. Добавить ребро `u→v`
    

**Почему сложность O(n²·2ⁿ)?**

- Состояний: `2ⁿ × n` (маска + конечная вершина)
    
- Для каждого состояния перебираем `n` возможных предыдущих вершин
    
- Итого: O(n²·2ⁿ)

#### **Псевдокод:**
```python
for mask in range(1 << n):
	for v in range(n):
		if not (mask & (1 << v)):
			continue
		
		prev_mask = mask ^ (1 << v)
		if prev_mask == 0:
			continue
		
		for u in range(n):
			if (prev_mask & (1 << u)) and dist[u][v] < INF:
				new_cost = dp[prev_mask][u] + dist[u][v]
				if new_cost < dp[mask][v]:
					dp[mask][v] = new_cost
```

#### **Ответ:**
```python
full_mask = (1 << n) - 1 # Содержит все вершины
min_cost = INF

for v in range(n):
	if dp[full_mask][v] < min_cost:
		min_cost = dp[full_mask][v]
```
