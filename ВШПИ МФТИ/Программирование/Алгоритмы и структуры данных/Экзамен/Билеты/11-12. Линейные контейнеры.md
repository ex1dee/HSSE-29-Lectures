## **Списки, Стек, Очередь, Дек**

### **1. Односвязный список (Singly Linked List)**

**Структура:** Узлы, каждый содержит:

- `value` — данные
- `next` — указатель на следующий узел (или `nullptr` для конца)

**Операции:**

- `InsertAfter(prev_node, value)`: O(1) — создали узел, перенаправили указатели
- `EraseAfter(prev_node)`: O(1) — перекинули указатель через узел
- `Find(value)`: O(n) — нужно пройтись по списку
- **Главная проблема:** Нет быстрого доступа по индексу, нельзя эффективно удалить текущий узел, зная только его (нужен указатель на предыдущий).

### **2. Двусвязный список (Doubly Linked List)**

**Структура:** Узлы содержат:

- `value`
- `next` — на следующий
- `prev` — на предыдущий

**Преимущества:**

- Можно удалять узел по указателю на него за O(1) (так как знаем предыдущий через `prev`)
- Можно итерировать в обе стороны
- **Стандартная реализация** `std::list` в C++, `list` в Python (на самом деле CPython list — динамический массив)

**Недостатки:** Больше памяти (2 указателя вместо 1).

---

### **3. Стек (LIFO — Last In First Out)**

**Интерфейс:**

- `push(x)` — добавить наверх
- `pop()` — снять сверху (и вернуть)
- `top()` — посмотреть верхний
- `empty()`, `size()`

**Реализации:**

1. **Через список (односвязный):**
    - `push` = добавить в голову O(1)
    - `pop` = удалить из головы O(1)
    - Минимум памяти, но есть накладные расходы на указатели
2. **Через динамический массив (вектор):**
    - `push` = `push_back` O(1) амортизированно
    - `pop` = `pop_back` O(1)
    - **Лучше на практике** из-за локальности данных.

---

### **4. Очередь (FIFO — First In First Out)**

**Интерфейс:**

- `enqueue(x)` или `push(x)` — в конец
- `dequeue()` или `pop()` — из начала
- `front()` — первый элемент
- `empty()`, `size()`

**Реализации:**

1. **Через двусвязный список:**
    
    - `push_back` + `pop_front` оба O(1)
        
    - Но много памяти на указатели
        
2. **Кольцевой буфер — оптимально:**
    
    - **Структура:** Массив фиксированного размера `capacity`, два индекса:
        
        - `head` (или `front`) — откуда забираем
            
        - `tail` (или `back`) — куда добавляем (указывает на следующую свободную ячейку)
            
    - **Логика:**
        
        ```cpp
        enqueue(x):
            if size == capacity: расширить или ошибка
            buffer[tail] = x
            tail = (tail + 1) % capacity
            size++
        
        dequeue():
            if empty(): ошибка
            x = buffer[head]
            head = (head + 1) % capacity
            size--
            return x
        ```
    - **Преимущества:**
        
        - O(1) на операции
        - Отличная локальность данных (все в массиве)
        - Минимум памяти (только массив + 2 индекса + size)

---

### **5. Дек (Deque — Double Ended Queue)**

**Интерфейс:** Очередь, но можно добавлять/удалять с двух концов:

- `push_front(x)`, `push_back(x)`
    
- `pop_front()`, `pop_back()`
    
- `front()`, `back()`
    

**Реализации:**

1. **Через двусвязный список:**
    
    - Все 4 основные операции за O(1)
        
    - Но много памяти
        
2. **Через кольцевой буфер (расширенный):**
    
    - Теперь `head` и `tail` могут двигаться в обе стороны:
        
        ```cpp
        push_front(x):
            head = (head - 1 + capacity) % capacity  // двигаем назад
            buffer[head] = x
            size++
        
        push_back(x):  // как enqueue
            buffer[tail] = x
            tail = (tail + 1) % capacity
            size++
        ```
        
    - **Проблема:** При `push_front` может "догнать" `tail`. Нужно либо расширять, либо изначально размещать в центре массива.
        
    - **Стандартная реализация (`std::deque`):** Массив указателей на блоки (например, по 512 элементов). Каждый блок — массив. Позволяет O(1) вставку в оба конца без дорогого расширения всего массива.

## **12. Очередь с поддержкой произвольной ассоциативной операции**

Это **мощная структура данных**, также известная как:

- **"Очередь с поддержкой операции"**
    
- **"Используя два стека"**
    
- **Очередь для задачи RMQ (Range Minimum Query) на скользящем окне**
    

### **1. Постановка задачи**

Нужна структура данных, которая поддерживает:

1. `push(x)` — добавить элемент в конец очереди
    
2. `pop()` — удалить элемент из начала очереди
    
3. `get_operation_result()` — вернуть результат применения ассоциативной операции `∘` ко **всем элементам текущей очереди** за O(1)
    

**Примеры операций:**

- `min` / `max` (чаще всего)
    
- `sum`, `gcd`, `xor`, `and`, `or`
    
- **Ассоциативность:** `(a ∘ b) ∘ c = a ∘ (b ∘ c)`
    

### **2. Реализация через два стека с накопленной операцией**

**Идея:** Представляем очередь как **два стека**:

- `stack_in` — для добавления (`push`)
    
- `stack_out` — для удаления (`pop`)
    

**Но не просто стек, а стек с дополнением:** В каждом стеке храним не только значения, но и **результат операции для префикса стека**.

cpp

struct StackWithOp {
    stack<Value> values;
    stack<Value> prefix_results; // результат операции для всего стека от низа до текущего
    
    void push(Value x) {
        values.push(x);
        if (prefix_results.empty()) {
            prefix_results.push(x);
        } else {
            Value prev = prefix_results.top();
            prefix_results.push(operation(prev, x)); // например, min(prev, x)
        }
    }
    
    Value get_result() {
        return prefix_results.empty() ? NEUTRAL : prefix_results.top();
    }
};

**Работа очереди:**

- `push(x)` → просто `stack_in.push(x)`
    
- `get_operation_result()` → `op(stack_in.get_result(), stack_out.get_result())`
    
- `pop()`:
    
    1. Если `stack_out` пуст: перекладываем **все** элементы из `stack_in` в `stack_out` (при перекладывании они инвертируются — это важно!)
        
    2. Удаляем из `stack_out`
        

### **3. Почему это работает за O(1) амортизированно?**

- `push` — O(1)
    
- `pop` — **амортизированно O(1)**, так как каждый элемент перекладывается из `stack_in` в `stack_out` только один раз
    
- `get_result` — O(1), так как берем `op(result_in, result_out)`
    

**Ключевой инвариант:**  
Очередь = `reverse(stack_out) + stack_in` (где `stack_out` перевернут относительно исходного порядка).  
Операция над всей очередью = операция над `stack_out` + операция над `stack_in`.

### **4. Пример для операции `min` (минимум в очереди)**

python

class MinQueue:
    def __init__(self):
        self.s1, self.s2 = [], []  # (value, current_min)
    
    def push(self, x):
        curr_min = x if not self.s1 else min(x, self.s1[-1][1])
        self.s1.append((x, curr_min))
    
    def pop(self):
        if not self.s2:
            while self.s1:
                x, _ = self.s1.pop()
                curr_min = x if not self.s2 else min(x, self.s2[-1][1])
                self.s2.append((x, curr_min))
        self.s2.pop()
    
    def get_min(self):
        if not self.s1 and not self.s2:
            return None
        if not self.s1:
            return self.s2[-1][1]
        if not self.s2:
            return self.s1[-1][1]
        return min(self.s1[-1][1], self.s2[-1][1])

**Применение:**

- Задача **"минимум в скользящем окне"** (Sliding Window Minimum) — классика!
    
- Кэширование результатов тяжёлых операций (например, НОК в очереди)
    
- Обработка потоков данных с необходимостью быстрого агрегирования
