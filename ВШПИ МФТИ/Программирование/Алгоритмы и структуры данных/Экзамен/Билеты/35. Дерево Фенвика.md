## **1. Постановка задачи и основные определения**

### **Задача:**

Дан массив `A[0..n-1]`. Нужно уметь:

1. **Находить сумму на отрезке** `[l, r]` за `O(log n)`
    
2. **Изменять элемент** `A[i]` за `O(log n)`
    

### **Эквивалентная формулировка:**

Достаточно уметь:

1. **Находить сумму на префиксе** `[0, m]` за `O(log n)`
    
2. **Увеличивать элемент** `A[k]` на `Δ` (любое) за `O(log n)`
    

**Почему эквивалентно:**  
`sum(l, r) = sum(0, r) - sum(0, l-1)`

## **2. Ключевые битовые функции**

### **Определение 1: Наибольший правый блок из единиц (НПБЕ)**

Для числа `x` в двоичной записи `x₁x₂...xₙ`:  
НПБЕ — это `xₖxₖ₊₁...xₙ`, где `k` минимально такое, что `∀j ∈ [k, n]: xⱼ = 1`.

**Пример:** `x = 101010101111`  
НПБЕ = `1111` (последние 4 бита)

---

### **Определение 2: Функция `f(x)`**

```text
f(x) = x & (x + 1)
```

**Утверждение 1:** `f(x)` — это `x` с занулённым НПБЕ.

**Доказательство:**  
Пусть `x = ... 0 111...111` (где 0 перед НПБЕ обязательно есть, иначе весь `x` — НПБЕ)

```text
x: ... 0 111...111
x+1: ... 1 000...000
x&(x+1): ... 0 000...000
```

Последние единицы в `x` стали нулями в `x+1`, побитовое И даёт 0. 

**Пример:**  
`x = 101010101111`  
`f(x) = 101010100000`

---

### **Определение 3: Функция `g(x)`**

```text
g(x) = x | (x + 1)
```


**Утверждение 2:** `g(x)` — это `x` с увеличенным НПБЕ на 1.

**Доказательство:**

```text
x: ... 0 111...111
x+1: ... 1 000...000
x|(x+1): ... 1 111...111
```

Единица перед блоком "распространяется" через ИЛИ на весь блок. □

**Пример:**  
`x = 101010101111`  
`g(x) = 101010111111`

---

### **Лемма 1: Монотонность**

Для любого `x ∈ ℤ⁺` верно: `f(g(x)) ≤ f(x)`.

**Доказательство:**  
В `g(x)` НПБЕ длиннее, чем в `x`.  
Применяя `f`, мы обнуляем НПБЕ.  
Чем длиннее был НПБЕ, тем больше битов обнулится, значит значение `f(g(x))` меньше или равно `f(x)`. 

**Пример:**  
`x = 11010101011111`  
`f(x) = 11010101010000`  
`g(x) = 11010101111111`  
`f(g(x)) = 11010100000000 < f(x)`

---

### **Лемма 2: Ограниченная итерация**

Для любого `x ∈ ℤ⁺` существует `n = O(log x)` такое, что:

```text
f(𝑓ⁿ(x)) = 0, где 𝑓̃(x) = f(x) - 1
```

**Доказательство:**

1. Рассмотрим последовательность:  
    `f(x), f(f(x)-1), f(f(f(x)-1)-1), ...`
    
2. Покажем, что она строго убывает:  
    `f(x) > f(f(x)-1)`
    
    Пусть НПБЕ в `x` начинается с позиции `k`.  
    Тогда `f(x)` обнуляет биты с `k` до конца.  
    `f(x)-1` превращает бит `k-1` в 1 и создаёт НПБЕ длиннее, чем в `x`.  
    Применяя `f` к `f(x)-1`, обнуляем более длинный блок → получаем меньшее число.
    
3. Так как значения строго убывают и ограничены снизу 0,  
    последовательность достигнет 0 за `O(log x)` шагов  
    (на каждом шаге "съедается" хотя бы один бит). □

## **3. Конструкция дерева Фенвика**

### **Определение 4: Дерево Фенвика**

Для массива `A[0..n-1]` дерево Фенвика — массив `F[0..n-1]`, где:

```text
F[m] = Σ_{k = f(m)}^{m} A[k]
```

То есть `F[m]` хранит сумму элементов `A` от `f(m)` до `m` включительно.

**Пример для n=8:**

```text
m:   0    1    2    3    4    5    6    7
f(m): 0    0    2    0    4    4    6    0
F[m]: A[0]  A[0..1]  A[2]  A[0..3]  A[4]  A[4..5]  A[6]  A[0..7]
```

## **4. Операция суммы на префиксе**

### **Алгоритм:**

cpp

int sum(int m) {
    int s = 0;
    for (; m >= 0; m = f(m) - 1) {
        s += F[m];
    }
    return s;
}

### **Теорема 1: Корректность суммы**

Алгоритм `sum(m)` корректно вычисляет `Σ_{k=0}^{m} A[k]`.

**Доказательство:**

1. По определению `F[m] = Σ_{k=f(m)}^{m} A[k]`
    
2. После прибавления `F[m]`, осталось вычислить сумму `Σ_{k=0}^{f(m)-1} A[k]`
    
3. Положим `m' = f(m) - 1`
    
4. По Лемме 2, последовательность `m, f(m)-1, f(f(m)-1)-1, ...` достигнет 0
    
5. На каждом шаге мы прибавляем сумму на непересекающихся отрезках:
    
    text
    
    [f(m), m] ∪ [f(f(m)-1), f(m)-1] ∪ ... = [0, m]
    
6. По Лемме 2, количество итераций `O(log m)` □
    

**Пример:** `sum(7)`

text

sum(7) = F[7] + F[6] + F[4] + F[0]
       = A[0..7] + A[6] + A[4] + A[0]
       = A[0] + A[1] + ... + A[7]

## **5. Операция обновления элемента**

### **Алгоритм:**

cpp

void add(int k, int delta) {
    for (; k < n; k = g(k)) {
        F[k] += delta;
    }
}

### **Теорема 2: Корректность обновления**

Алгоритм `add(k, delta)` корректно обновляет все `F[m]`, для которых `f(m) ≤ k ≤ m`.

**Доказательство:**

1. **База:** `m = k`  
    Очевидно, `f(k) ≤ k ≤ k`, значит `F[k]` нужно обновить.
    
2. **Индукционный переход:**  
    Пусть обновили `m`. Покажем, что следующий индекс — `g(m)`.
    
    Из Леммы 1: `f(g(m)) ≤ f(m)`  
    Также: `m < g(m)` (по определению `g`)
    
    Поэтому: `f(g(m)) ≤ f(m) ≤ k < m < g(m)`  
    Значит: `f(g(m)) ≤ k < g(m)` → `F[g(m)]` нужно обновить.
    
3. **Достаточность:**  
    Нужно показать, что других индексов обновлять не нужно.
    
    Пусть существует `m > k`, не представимый как `gⁿ(k)`, но такой что `f(m) ≤ k < m`.
    
    Рассмотрим `k₀ = k` с обнулёнными последними `p` битами, где `p` — длина НПБЕ в `m`.
    
    - Если `k` лежит в последних `p` битах `m`, то `k₀ = f(m)`
        
    - Иначе `k₀ > f(m)`
        
    
    Второй случай приводит к противоречию: `k > m`.
    
    Значит `k₀ = f(m)`. Применяя `g` к `k₀` `p` раз, получим `m`.
    
    Но `k₀` — это `k` с обнулённым суффиксом, значит существует `t` такое, что `gᵗ(k) = gᵖ(k₀) = m`.
    
    Противоречие с предположением, что `m` не представим как `gⁿ(k)`. □
    

**Сложность:** `O(log n)` — на каждой итерации устанавливается хотя бы один бит.

## **6. Построение дерева**

### **Алгоритм 1: Наивное построение** `O(n log n)`

cpp

vector<int> build_naive(vector<int>& A) {
    vector<int> F(A.size(), 0);
    for (int i = 0; i < A.size(); i++) {
        add(i, A[i]);  // O(log n) каждая
    }
    return F;
}

### **Алгоритм 2: Оптимальное построение** `O(n)`

cpp

vector<int> build_fast(vector<int>& A) {
    int n = A.size();
    vector<int> F(n, 0);
    
    // 1. Строим префиксные суммы
    F[0] = A[0];
    for (int i = 1; i < n; i++) {
        F[i] = F[i - 1] + A[i];
    }
    
    // 2. Преобразуем в дерево Фенвика
    for (int i = n - 1; i >= 0; i--) {
        int fi = f(i) - 1;
        if (fi >= 0) {
            F[i] -= F[fi];
        }
    }
    
    return F;
}

### **Теорема 3: Корректность построения**

Алгоритм `build_fast` строит корректное дерево Фенвика.

**Доказательство:**  
После шага 1: `F[i] = S(i) = Σ_{k=0}^{i} A[k]`

Нужно получить: `F[i] = Σ_{k=f(i)}^{i} A[k] = S(i) - S(f(i)-1)`

На шаге 2 для `i`:

- `F[i]` ещё не изменялся → содержит `S(i)`
    
- `F[f(i)-1]` ещё не изменялся → содержит `S(f(i)-1)`
    
- После вычитания: `F[i] = S(i) - S(f(i)-1)` — корректное значение
    

Так как идём с конца, для каждого `i` требуемые префиксные суммы ещё не были изменены. □

## **7. Обобщение на многомерный случай**

### **Определение 5: d-мерное дерево Фенвика**

Для массива `A` размерности `n₁ × n₂ × ... × nₙ`:

text

F[a₁][a₂]...[aₙ] = Σ_{k₁=f(a₁)}^{a₁} Σ_{k₂=f(a₂)}^{a₂} ... Σ_{kₙ=f(aₙ)}^{aₙ} A[k₁][k₂]...[kₙ]

### **Алгоритм суммы в 2D:**

cpp

int sum_2d(int a, int b) {
    int s = 0;
    for (int i = a; i >= 0; i = f(i) - 1) {
        for (int j = b; j >= 0; j = f(j) - 1) {
            s += F[i][j];
        }
    }
    return s;
}

### **Алгоритм обновления в 2D:**

cpp

void add_2d(int a, int b, int delta) {
    for (int i = a; i < n1; i = g(i)) {
        for (int j = b; j < n2; j = g(j)) {
            F[i][j] += delta;
        }
    }
}

### **Теорема 4: Корректность 2D операций**

Алгоритмы `sum_2d` и `add_2d` корректны и работают за `O(log n₁ log n₂)`.

**Доказательство:**  
По индукции:

- Внутренний цикл обрабатывает вторую координату как в 1D случае
    
- Внешний цикл обрабатывает первую координату
    
- Каждый работает за `O(log n)`
    
- Корректность следует из дистрибутивности суммирования:
    
    text
    
    Σ_{i=0}^{a} Σ_{j=0}^{b} A[i][j] = 
    Σ_{i=f(a)}^{a} (Σ_{j=0}^{b} A[i][j]) + Σ_{i=f(f(a)-1)}^{f(a)-1} (Σ_{j=0}^{b} A[i][j]) + ...
    
    Затем каждую внутреннюю сумму раскладываем аналогично. □

## **8. Требования к операции**

### **Необходимые свойства:**

1. **Ассоциативность** — `(a ∘ b) ∘ c = a ∘ (b ∘ c)`  
    _Нужно для разбиения суммы на части_
    
2. **Обратимость** — существование обратной операции `⊖`  
    _Нужно для вычисления суммы на отрезке через префиксы_
    
3. **Коммутативность** — `a ∘ b = b ∘ a`  
    _Нужно для обновлений (порядок не важен)_
    

### **Примеры:**

- **Сумма:** `+` (ассоциативна, коммутативна), обратная — `-` ✓
    
- **Произведение:** `×` (ассоциативна, коммутативна), обратная — `÷` ✓  
    (нужно избегать деления на 0)
    
- **XOR:** `⊕` (ассоциативна, коммутативна), обратная — `⊕` ✓
    
- **Минимум/максимум:** необратимы ❌

## **10. Итог**

### **Когда использовать дерево Фенвика:**

1. Нужны только **точечные обновления** (нет запросов на отрезке)
    
2. Операция **ассоциативна, обратима и коммутативна**
    
3. Важна **простота реализации** и **экономия памяти**
    
4. Нужны **многомерные запросы**
    

### **Ключевые идеи для запоминания:**

1. `f(x) = x & (x+1)` — зануляет последние единицы
    
2. `g(x) = x | (x+1)` — увеличивает блок единиц
    
3. **Сумма:** идём `m → f(m)-1 → f(f(m)-1)-1 → ... → 0`
    
4. **Обновление:** идём `k → g(k) → g(g(k)) → ... < n`
    
5. **2D:** вложенные циклы с теми же правилами
    

### **Фундаментальные теоремы:**

1. Последовательность `fⁿ(x)` достигает 0 за `O(log n)` шагов
    
2. Обновлять нужно только `gⁿ(k)`
    
3. Построение за `O(n)` через преобразование префиксных сумм
