## Зачем нужен алгоритм

**Тернарный поиск** используется для нахождения максимума или минимума (экстремума) функции на отрезке, если эта функция обладает свойством **унимодальности**.

**Что дано:** 
- Отрезок $[l, r]$.

- Унимодальная функция $f(x)$, которая на этом отрезке сначала строго возрастает, а затем строго убывает (для поиска максимума), либо наоборот — сначала убывает, а затем возрастает (для поиска минимума).
    

**Что находит:**

- Точку $x_{max}$ (или $x_{min}$), в которой функция достигает своего экстремального значения, с заданной точностью $\epsilon$.
    

## Суть и корректность алгоритма

В отличие от бинарного поиска, который делит отрезок пополам одной точкой, тернарный поиск делит текущий отрезок $[l, r]$ на **три равные части** с помощью двух точек: $m_1$ и $m_2$.

$$m_1 = l + \frac{r - l}{3}$$

$$m_2 = r - \frac{r - l}{3}$$

Рассмотрим случай поиска **максимума** для функции, которая сначала возрастает, а затем убывает:

1. Если $f(m_1) < f(m_2)$, это означает, что максимум точно не может находиться на левом отрезке $[l, m_1]$. Он гарантированно лежит в промежутке $[m_1, r]$. Мы сдвигаем левую границу: $l = m_1$.
    
2. Если $f(m_1) > f(m_2)$, это означает, что максимум точно не может находиться на правом отрезке $[m_2, r]$. Он гарантированно лежит в промежутке $[l, m_2]$. Мы сдвигаем правую границу: $r = m_2$.
    
3. Если $f(m_1) = f(m_2)$, максимум находится между ними, и можно сдвинуть обе границы ($l = m_1, r = m_2$), либо любую из них.
    

Таким образом, на каждом шаге длина рассматриваемого отрезка уменьшается ровно в $\frac{2}{3}$ раза. Процесс повторяется до тех пор, пока длина отрезка не станет меньше заданной точности $\epsilon$ (для вещественных чисел) или пока границы не сойдутся (для целых чисел).

## Асимптотика

### Временная сложность: $\mathcal{O}(\log_{1.5} \frac{r - l}{\epsilon})$

На каждой итерации длина отрезка умножается на $\frac{2}{3}$. Чтобы уменьшить отрезок от исходной длины $L = r - l$ до величины $\epsilon$, требуется $k$ шагов:

$$\left(\frac{2}{3}\right)^k \cdot L \le \epsilon \implies k \approx \log_{1.5} \left(\frac{r - l}{\epsilon}\right)$$

Так как основание логарифма влияет только на константу, асимптотика эквивалентна логарифмической: **$\mathcal{O}(\log \frac{r-l}{\epsilon})$**. На каждом шаге происходит ровно два вычисления значения функции $f(x)$.

### Пространственная сложность: $\mathcal{O}(1)$

Алгоритм требует константного количества дополнительной памяти для хранения границ и точек деления.

## Пример кода (C++)

Ниже представлена реализация тернарного поиска максимума для вещественной функции.

```cpp
#include <iostream>
#include <cmath>
#include <iomanip>

// Пример унимодальной функции (парабола ветвями вниз, максимум в x = 2.0)
double f(double x) {
    return -1.0 * (x - 2.0) * (x - 2.0) + 5.0;
}

// Тернарный поиск максимума функции f на отрезке [l, r]
double ternary_search_max(double l, double r, double eps = 1e-9) {
    while (r - l > eps) {
        double m1 = l + (r - l) / 3.0;
        double m2 = r - (r - l) / 3.0;

        if (f(m1) < f(m2)) {
            l = m1; // Максимум в [m1, r]
        } else {
            r = m2; // Максимум в [l, m2]
        }
    }
    return (l + r) / 2.0; // Возвращаем центр получившегося микро-отрезка
}

int main() {
    double l = -10.0, r = 10.0;
    double x_max = ternary_search_max(l, r);
    
    std::cout << std::fixed << std::setprecision(6);
    std::cout << "Точка максимума x: " << x_max << std::endl;
    std::cout << "Максимальное значение f(x): " << f(x_max) << std::endl;
    
    return 0;
}
```

> [!WARNING] **Опасные моменты**
> 
> 1. **Дискретный тернарный поиск (на целых числах):** При работе с целыми индексами формулы деления `(r - l) / 3` из-за округления могут привести к зацикливанию, когда отрезок станет очень маленьким (например, длины 2 или 3).
>     
>     _Решение:_ Выполнять `while (r - l > 2)`, а оставшиеся 2-3 точки проверить обычным перебором (if-ами).
>     
> 2. **Плато (стационарные участки):** Если функция содержит участки, где её значение постоянно ($f(x) = const$), тернарный поиск может отрезать часть отрезка, содержащую истинный экстремум, поскольку условие строгого возрастания/убывания нарушается.
>
