### Представления графов

##### 1. Матрица смежности
- **Хранится:** массив размера $|V| \times |V|$, где $a[i][j] = 1$, если есть ребро из $i$ в $j$, иначе $0$
- **Взвешенный граф:** $a[i][j]$ содержит вес ребра 

##### 2. Список смежности
- **Хранится:** массив списков размера $|V|$, где для каждой вершины $v$ хранится список её соседей
- **Взвешенный граф:** храним пары $(сосед, вес)$

##### Сравнение представлений

| Операция                | Матрица смежности | Список смежности               |
| ----------------------- | ----------------- | ------------------------------ |
| Проверить наличие ребра | $O(1)$            | $O(\deg v)$ (в среднем $O(1)$) |
| Получить всех соседей   | $O(\|V\|)$        | $O(\deg v)$                    |
| Память                  | $O(\|V\|^2)$      | $O(\|V\| + \|E\|)$             |
| Построение              | $O(\|V\|^2)$      | $O(\|V\| + \|E\|)$             |
| Добавить ребро          | $O(1)$            | $O(1)$ в среднем               |

- Матрица смежности эффективна для плотных графов ($|E| \approx |V|^2$)
- Список смежности эффективен для разреженных графов ($|E| \ll |V|^2$)

### Поиск в глубину (Depth-First Search, DFS)

##### Алгоритм

```cpp
vector<bool> used(n, false); // массив посещённых вершин

void dfs(const vector<vector<int>>& graph, int v) {
    used[v] = true; // помечаем вершину как посещённую
    
    // обходим всех соседей
    for (int u : graph[v]) {
        if (!used[u]) {
            dfs(graph, u); // рекурсивный вызов для непосещённых соседей
        }
    }
}
```

**Время работы:** $O(|V| + |E|)$

### Модификации DFS

##### 1. Трёхцветная раскраска вершин
Используем три состояния вершин:

1. **Белый (WHITE)** — вершина не посещена
2. **Серый (GRAY)** — вершина посещена, но не обработана (мы вошли в неё, но не вышли)
3. **Чёрный (BLACK)** — вершина полностью обработана (вошли и вышли)

**Алгоритм:**
```cpp
enum Color { WHITE, GRAY, BLACK };
vector<Color> color(n, WHITE);
vector<int> time_in(n), time_out(n);
int timer = 0;

void dfs(const vector<vector<int>>& graph, int v) {
    color[v] = GRAY;
    time_in[v] = timer++;
    
    for (int u : graph[v]) {
        if (color[u] == WHITE) {
            dfs(graph, u);
        }
    }
    
    color[v] = BLACK;
    time_out[v] = timer++;
}
```

##### 2. Подсчёт компонент связности

```cpp
int count_components(const vector<vector<int>>& graph) {
    int components = 0;
    
    for (int v = 0; v < graph.size(); ++v) {
        if (!used[v]) {
            ++components;
            dfs(graph, v); // заполнит used для всей компоненты
        }
    }
    
    return components;
}
```

**Пояснение:** DFS обходит все вершины, достижимые из стартовой. Каждый новый запуск DFS из непосещённой вершины соответствует новой компоненте связности.

##### 3. Проверка на ацикличность

```cpp
bool has_cycle = false;

void dfs_detect_cycle(const vector<vector<int>>& graph, int v) {
    color[v] = GRAY;
    
    for (int u : graph[v]) {
        if (color[u] == WHITE) {
            dfs_detect_cycle(graph, u);
        } else if (color[u] == GRAY) {
            // Нашли ребро к серой вершине — это обратное ребро, означает цикл
            has_cycle = true;
        }
    }
    
    color[v] = BLACK;
}
```

**Утверждение:** В ориентированном графе есть цикл тогда и только тогда, когда в процессе DFS найдётся ребро, ведущее в серую вершину.

### Лемма о белых путях

> **Лемма о белых путях.**
> Рассмотрим все вершины, достижимые из вершины $u$ по белым путям в момент, когда $u$ становится серой. В момент, когда $u$ становится чёрной, все эти вершины станут чёрными.

*Доказательство (от противного):*
- Пусть существует вершина $w$, достижимая из $u$ по белому пути, которая осталась белой в момент $t_{out}(u)$ (когда $u$ стала черной).
    
- Рассмотрим путь $u = v_0, v_1, \dots, v_k = w$, который был целиком белым в момент $t_{in}(u)$.
    
- На этом пути обязательно найдется **последняя** вершина $v_i$, которая успела стать черной (или хотя бы серой) до момента $t_{out}(u)$, в то время как её сосед $v_{i+1}$ остался белым.
    
- В какой-то момент времени мы находились в вершине $v_i$ (она была серой).
    
- По алгоритму DFS, мы обязаны перебрать всех соседей $v_i$, включая $v_{i+1}$.
    
- Если в этот момент $v_{i+1}$ все еще была белой, мы были **обязаны** вызвать $dfs(v_{i+1})$.
    
- Согласно свойствам стека рекурсии, $v_{i+1}$ не могла бы остаться белой к моменту завершения $v_i$, а значит, и к моменту завершения $u$ – **противоречие**

##### Следствия из леммы

1. **DFS от вершины $v$ посетит все достижимые из $v$ вершины (и только их).**
   - Это прямо следует из леммы: все вершины, достижимые из $v$, лежат на белых путях в момент начала обхода

2. **Критерий ацикличности:**
   - Граф ациклический $\iff$ в DFS нет рёбер ($u$ серая, $v$ серая)

#### Топологическая сортировка

**Топологическая сортировка** орграфа — это перестановка вершин $\sigma \in S_{|V|}$, такая что:
$$\forall (u, v) \in E: \sigma(u) < \sigma(v)$$

### 5.2. Теорема о существовании
> Топологическая сортировка существует $\iff$ когда граф **ациклический**

**Доказательство:**

**(→) Пусть топологическая сортировка существует, но есть цикл $u_1 \to u_2 \to \dots \to u_k \to u_1$.**  
По определению топологической сортировки:
$$\sigma(u_1) < \sigma(u_2) < \dots < \sigma(u_k) < \sigma(u_1)$$
Получаем $\sigma(u_1) < \sigma(u_1)$ — противоречие.

**(←) Пусть граф ациклический. Докажем, что можно построить топологическую сортировку.**  
Рассмотрим времена выхода из вершин $t_{out}[v]$ в DFS. Утверждаем, что если $(u, v) \in E$, то $t_{out}[u] > t_{out}[v]$.

**Доказательство утверждения:**
1. **Случай 1:** $t_{in}[u] < t_{in}[v]$ (вошли в $u$ раньше, чем в $v$)
   - Из $u$ есть ребро в $v$, значит $v$ достижима из $u$
   - По лемме о белых путях, обработка $v$ закончится до того, как закончится обработка $u$
   - Следовательно: $t_{out}[u] > t_{out}[v]$
   
2. **Случай 2:** $t_{in}[u] > t_{in}[v]$ (вошли в $v$ раньше, чем в $u$)
   - Если бы $v$ была достижима из $u$, то образовался бы цикл (по лемме о белых путях)
   - Граф ациклический, значит $v$ не достижима из $u$
   - Тогда $v$ закончит обработку до того, как мы начнём обрабатывать $u$
   - Следовательно: $t_{out}[v] < t_{in}[u] < t_{out}[u]$

Таким образом, для любого ребра $(u, v)$ выполняется $t_{out}[u] > t_{out}[v]$. Значит, если отсортировать вершины по **убыванию** $t_{out}$, то для любого ребра $(u, v)$ начало будет раньше конца в этом порядке.

### 5.3. Алгоритм построения топологической сортировки

```cpp
vector<int> order; // результат - топологический порядок

void dfs_topological(const vector<vector<int>>& graph, int v) {
    color[v] = GRAY;
    
    for (int u : graph[v]) {
        if (color[u] == WHITE) {
            dfs_topological(graph, u);
        }
    }
    
    color[v] = BLACK;
    order.push_back(v); // добавляем вершину при выходе
}

vector<int> topological_sort(const vector<vector<int>>& graph) {
    int n = graph.size();
    color.assign(n, WHITE);
    order.clear();
    
    for (int v = 0; v < n; ++v) {
        if (color[v] == WHITE) {
            dfs_topological(graph, v);
        }
    }
    
    reverse(order.begin(), order.end()); // разворачиваем, так как добавляли при выходе
    return order;
}
```

**Важно:** Этот алгоритм работает только для **ациклических** графов. Для графов с циклами он либо обнаружит цикл, либо выдаст некорректный порядок.

## 6. Дополнительные свойства времен DFS

- **Интервал активности вершины:** $[t_{in}[v], t_{out}[v]]$
- **Вложение интервалов:** Если $u$ — потомок $v$ в DFS-дереве, то интервал $u$ полностью содержится в интервале $v$
- **Непересечение интервалов:** Если $u$ и $v$ не связаны отношением предок-потомок, их интервалы не пересекаются

**Эти свойства полезны для:**
- Проверки, является ли одна вершина предком другой в DFS-дереве ($O(1)$ по временам входа/выхода)
- Решения задач на наименьшего общего предка (LCA)
- Анализа структуры графа

---

**Итог:** Поиск в глубину — фундаментальный алгоритм обхода графов с многочисленными применениями: от поиска компонент связности и обнаружения циклов до топологической сортировки и анализа структуры графа. Ключевые идеи — трёхцветная раскраска, времена входа/выхода и лемма о белых путях — позволяют доказывать корректность алгоритмов и строить эффективные решения.
