#### **1. Определение и основная идея**

**Splay-дерево** — это **самобалансирующееся** бинарное дерево поиска **без явного хранения баланс-фактора** (как height или priority).

**Ключевая идея (принцип локальности):**

- После любой операции (`Find`, `Insert`, `Erase`) с элементом `X` выполняется специальная операция **`Splay(X)`**.
    
- `Splay(X)` **"поднимает"** узел `X` в корень дерева с помощью последовательности поворотов.
    
- **Цель:** Часто используемые элементы оказываются близко к корню, что ускоряет доступ к ним (принцип **"кэширования"**).
    

**Важно:** Splay-дерево **не гарантирует** сбалансированность в каждый момент. Но **амортизированная** сложность операций составляет `O(log n)`.

#### **2. Операция `Splay(x)`**

Операция выполняется, пока узел `x` не станет корнем. Используются **три типа шагов (zig, zig-zig, zig-zag)** в зависимости от позиции `x`, его родителя `p` и деда `g`.

**Обозначения:**

- `x` — поднимаемый узел.
    
- `p` — родитель `x`.
    
- `g` — родитель `p` (дед `x`).
    

##### **Шаг 1: Zig (одиночный поворот)**

**Выполняется, когда `p` — корень дерева.**

- Если `x` — **левый** ребёнок `p` → правое вращение вокруг `p` (как в AVL).
    
- Если `x` — **правый** ребёнок `p` → левое вращение вокруг `p`.
    

```text
    p          x
   / \   ->   / \
  x   C      A   p
 / \            / \
A   B          B   C
```

##### **Шаг 2: Zig-zig**

**Выполняется, когда `x` и `p` оба **левые** или оба **правые** дети.  
Сначала поворот вокруг `g`, затем вокруг `p`.

- **Случай LL (x — левый ребёнок p, p — левый ребёнок g):**
    
    1. Правое вращение вокруг `g`.
        
    2. Правое вращение вокруг `p`.
        
```text
      g            p           x
     / \          / \        /   \
    p   D  ->    x   g  ->  A     p
   / \          / \ / \          / \
  x   C         A B C D         B   g
 / \                               / \
A   B                             C   D
```

##### **Шаг 3: Zig-zag**

**Выполняется, когда `x` и `p` — разносторонние дети** (x — левый, p — правый или наоборот).  
Сначала поворот вокруг `p`, затем вокруг `g`.

- **Случай LR (x — правый ребёнок p, p — левый ребёнок g):**
    
    1. Левое вращение вокруг `p`.
        
    2. Правое вращение вокруг `g`.
        
```text
    g              g              x
   / \            / \            / \
  p   D   ->     x   D   ->     p   g
 / \            / \            / \ / \
A   x          p   C          A B C D
   / \        / \
  B   C      A   B
```

#### **3. Теорема о времени работы операции `Splay` (аморт. анализ)**

**Утверждение:** Амортизированное время операции `Splay(x)` в дереве с `n` узлами есть **`O(log n)`**.

#### **1. Потенциал**

Вводим **потенциал** всего дерева `Φ`, который помогает "копить" оплату за быстрые операции и тратить её на медленные.

**Определение потенциала:**

- Пусть для каждого узла `v` определён его **размер** `size(v)` — количество узлов в поддереве с корнем в `v`.
    
- Определим его **ранг**: `r(v) = log₂(size(v))`.
    
- **Потенциал дерева** `Φ = Σ r(v)` (сумма рангов по всем узлам `v` в дереве).
    

**Свойства:**

- `0 ≤ Φ ≤ n log n`.
    
- После `Splay` потенциал может как увеличиться, так и уменьшиться.
    

#### **2. Амортизированная стоимость**

Пусть `t` — реальное время шага (число поворотов × `O(1)`), `ΔΦ` — изменение потенциала.  
**Амортизированная стоимость шага:** `a = t + ΔΦ`.

**Нам нужно доказать, что:**

1. Амортизированная стоимость **одного шага (Zig, Zig-zig, Zig-zag)** есть `O(1)` (точнее, ≤ `3(r'(x) - r(x))` для Zig-zig/zig-zag и ≤ `1 + 3(r'(x) - r(x))` для Zig, где `r(x)` — ранг до шага, `r'(x)` — после).
    
2. Тогда, суммируя по всем шагам `Splay`, амортизированная стоимость всей операции будет:  
    `A ≤ 1 + 3(r(root) - r(x)) = 1 + 3*log(size(root)/size(x)) ≤ 1 + 3*log n = O(log n)`.
    

#### **3. Разбор случаев (схема доказательства)**

##### **Случай Zig (p — корень)**
`ΔΦ = (r'(x) + r'(p)) - (r(x) + r(p))`
`a = 1 + (r'(x) + r'(p)) - (r(x) + r(p))`


```text
    p          x
   / \   ->   / \
  x   C      A   p
 / \            / \
A   B          B   C
```

- **Размеры:**
    
    - `size'(x) = size(p)` (всё поддерево осталось тем же).
        
- Следовательно:
    
    - `r'(x) = r(p)` (т.к. `size'(x) = size(p)`).
        
    - `r'(p) ≤ r'(x)` (т.к. `size'(p) < size'(x)`).
        

Подставляем в формулу для `a`:

```text
a = 1 + (r'(x) + r'(p)) - (r(x) + r(p))
  = 1 + (r(p) + r'(p)) - (r(x) + r(p))
  = 1 + r'(p) - r(x) ≤ 1 + r'(x) - r(x) ≤ 1 + 3(r'(x) - r(x))
```

##### **Случай Zig-zig (x и p — оба левые дети)**

`ΔΦ = (r'(x) + r'(p) + r'(g)) - (r(x) + r(p) + r(g))`
`a = 2 + (r'(x) + r'(p) + r'(g)) - (r(x) + r(p) + r(g))`

```text
      g            p           x
     / \          / \        /   \
    p   D  ->    x   g  ->  A     p
   / \          / \ / \          / \
  x   C         A B C D         B   g
 / \                               / \
A   B                             C   D
```


**Ключевые соотношения размеров:**

1.   `size'(x) = size(g)` ⇒ `r'(x) = r(g)`.
    
2. `size(g) ≥ size(p) + 1` и `size(p) ≥ size(x) + 1`.

Тогда:
`a = 2 + (r(g) + r'(p) + r'(g)) - (r(x) + r(p) + r(g))`  
`a = 2 + r'(p) + r'(g) - r(x) - r(p)`

**Теперь главная техническая лемма:**  
Для конфигурации Zig-zig выполняется:  
`r'(p) + r'(g) ≤ 2r'(x) - 2` (т.к. `size'(p) + size'(g) ≤ size'(x)` и поддеревья не пересекаются).

Доказательство леммы:

- После шага узлы `p` и `g` — дети `x`, их поддеревья не пересекаются.
    
- `size'(p) + size'(g) < size'(x)` (так как не включают сам узел `x`).
    
- Из свойства логарифма: если `a + b ≤ c`, то `log a + log b ≤ 2 log c - 2`.
    

Подставляем эту лемму (`r'(p) + r'(g) ≤ 2r'(x) - 2`):

text

a ≤ 2 + [2r'(x) - 2] - r(x) - r(p)
  = 2r'(x) - r(x) - r(p)

Теперь используем, что до шага `r(p) ≥ r(x)` (так как `x` — ребёнок `p`), поэтому `-r(p) ≤ -r(x)`:

text

a ≤ 2r'(x) - 2r(x)

Добавляем `r'(x) - r(x)` (неотрицательное) справа:

text

a ≤ 3r'(x) - 3r(x) = 3(r'(x) - r(x))

---

#### **Случай Zig-zag (x — правы^&&&&й ребёнок, p — левый ребёнок)**

text

    g              g              x
   / \            / \            / \
  p   D   ->     x   D   ->     p   g
 / \            / \            / \ / \
A   x          p   C          A B C D
   / \        / \
  B   C      A   B

**Аналогично Zig-zig:**

1. После шага `size'(x) = size(g)` ⇒ `r'(x) = r(g)`.
    
2. Та же лемма: `r'(p) + r'(g) ≤ 2r'(x) - 2` (поддеревья `p` и `g` не пересекаются и оба содержатся в поддереве `x`).
    
3. Подстановка даёт ту же оценку: `a ≤ 3(r'(x) - r(x))`.
#### **4. Следствие для операций**

Так как `Find`, `Insert`, `Erase` выражаются через `Splay` + `O(1)` дополнительных действий, их **амортизированная** сложность также `O(log n)`.

**Важно:** Это **амортизированная** оценка. Отдельная операция может занять `O(n)` времени, но **последовательность из m операций** займёт `O(m log n)`.

### **2. Выразимость остальных операций через Splay**

Все основные операции BST выражаются через `Splay` и базовые манипуляции.

#### **1. `Find(key)`**

1. Обычным спуском в BST находим узел с ключом `key` (или последний посещённый узел, если ключ не найден).
    
2. Выполняем **`Splay`** для найденного узла (или для последнего посещённого, если ключа нет).
    
3. **Результат:**
    
    - Если ключ найден — он теперь в корне.
        
    - Если ключа нет — в корне оказывается либо максимальный элемент из левого поддерева, либо минимальный из правого (в зависимости от реализации поиска).
        

#### **2. `Insert(key)`**

1. **Если дерево пустое:** создаём новый узел — он корень.
    
2. **Иначе:**
    
    - Выполняем `Find(key)`. После этого в корне `root` находится:
        
        - Сам `key`, если он уже был (тогда вставка не нужна).
            
        - Ближайший к `key` узел (предшественник или последователь).
            
    - **Если `key` нет:** сравниваем `key` с `root->key`.
        
        - Если `key < root->key`:
            
            - Делаем `root` **правым** ребёнком нового узла.
                
            - Левого ребёнка `root` делаем **левым** ребёнком нового узла.
                
            - Обнуляем левого ребёнка у `root`.
                
        - Если `key > root->key` (симметрично):
            
            - Делаем `root` **левым** ребёнком нового узла.
                
            - Правого ребёнка `root` делаем **правым** ребёнком нового узла.
                
            - Обнуляем правого ребёнка у `root`.
                
    - Новый узел становится корнем.
        

**Наглядный случай `key < root->key` (после Find):**

text

    root (ближайший > key)
   /
  L   <- содержит все ключи < key
 / \
... ...

Вставляем новый узел `x`:

text

      x (новый корень)
     / \
    L   root
       /
    (остальное)

#### **3. `Erase(key)`**

1. Выполняем `Find(key)`. Если ключа нет (в корне другой элемент) — завершаем.
    
2. Если ключ есть, он теперь в корне.
    
3. **Удаляем корень:**
    
    - Если нет одного из детей → оставшегося ребёнка делаем новым корнем.
        
    - **Если есть оба ребёнка:**
        
        1. Отделяем левое поддерево (`L`).
            
        2. В правом поддереве (`R`) находим минимальный элемент (`FindMin` без финального Splay или с ним).
            
        3. После этого минимальный элемент `R` будет в корне правого поддерева **и не будет иметь левого ребёнка**.
            
        4. **Подвешиваем** `L` как левое поддерево к новому корню `R`.
            
        5. Новый корень — `R`.
            

**Альтернативный метод через Split/Merge:**

1. `Splay(key)` → ключ в корне.
    
2. Отрезаем левое поддерево `L` и правое `R`.
    
3. `Merge(L, R)` (сливаем два BST, где все ключи в `L` < всех ключей в `R`):
    
    - В `L` делаем `Splay(MAX)` — максимальный элемент `L` поднимется в корень `L` и не будет правого ребёнка.
        
    - Подвешиваем `R` как правое поддерево к корню `L`.
        
4. Новый корень — корень `L`.
    

#### **4. `Split(key)` и `Merge(L, R)`**

- **`Split(key, root)`** — разделить дерево на два: `< key` и `>= key`.
    
    1. `Find(key)` (или нижняя граница).
        
    2. После `Splay` в корне будет элемент `>= key`.
        
    3. Если корень `>= key` → отрезаем левое поддерево. Получаем `L` и `R`.
        
- **`Merge(L, R)`** — слить два дерева, где все ключи в `L` < всех ключей в `R`.
    
    1. В `L` делаем `Splay(MAX)` — максимальный элемент станет корнем `L` без правого ребёнка.
        
    2. Подвешиваем `R` как правое поддерево к `L`.

### **Итог: Сравнение с другими BST**

|Свойство|**Splay-дерево**|**AVL**|**Декартово**|
|---|---|---|---|
|**Балансировка**|Амортизированная, эвристическая|Строгая, детерминированная|Вероятностная|
|**Гарантия**|**Амортизированная** `O(log n)`|**Строгая** `O(log n)`|**Ожидаемая** `O(log n)`|
|**Принцип**|Локальность (поднимает часто используемые)|Глобальная сбалансированность|Случайные приоритеты|
|**Константы**|Малые (нет доп. полей)|Есть доп. поле `height`/`bf`|Есть поле `priority`|
|**Операции**|Всё через `Splay`|Стандартные BST + балансировка|Всё через `Split`/`Merge`|
