### **1. Мотивация и постановка задачи**

**Проблема**: Анализ отдельных операций алгоритма (например, `push` в динамическом массиве) может показывать высокую **пиковую** стоимость (`O(n)` при расширении), в то время как на длинной последовательности операций **средняя** стоимость оказывается низкой.

**Цель амортизационного анализа**: Дать **гарантированную верхнюю оценку средней стоимости операции** в **наихудшем случае** для **последовательности операций**. Это **не** вероятностный анализ.

**Формально**: Для последовательности из `n` операций с реальными стоимостями `t₁, t₂, ..., tₙ` нужно найти **амортизированную стоимость** `a`, такую что:  
`Σ tᵢ ≤ Σ aᵢ = n * a`. Тогда `a` — амортизированная стоимость одной операции.

---

### **2. Три основных метода анализа**

#### **2.1. Групповой (агрегатный) анализ**

**Идея**: Показать, что для **любой** последовательности из `n` операций **суммарное** время `T(n) = O(f(n))`. Тогда амортизированная стоимость равна `O(f(n))/n`.

**Пример: Стек с MULTIPOP**

- **Операции**:
    
    - `PUSH(S, x)`: `O(1)`.
        
    - `POP(S)`: `O(1)`.
        
    - `MULTIPOP(S, k)`: извлекает `min(k, |S|)` верхних элементов. Реальная стоимость `O(k)`.
        
- **Анализ**: Элемент может быть вытолкнут из стека (через `POP` или `MULTIPOP`) **только один раз** за всё время. Число операций `PUSH` ≤ `n`. Следовательно, общее число вызовов `POP` (включая внутри `MULTIPOP`) ≤ `n`.
    
- **Вывод**: `T(n) = O(n)`. Амортизированная стоимость **любой** операции: `a = T(n)/n = O(1)`.
    

#### **2.2. Метод бухгалтерского учёта (метод монеток)**

**Идея**: Каждой операции назначается **амортизированная стоимость** `aᵢ`. Если `aᵢ > tᵢ` (реальная стоимость), разница зачисляется как **"кредит"** (монетки) на определённые элементы структуры данных. Если `aᵢ < tᵢ`, работа оплачивается из накопленного кредита.

**Требование**: **Суммарный кредит всегда неотрицателен**.  
`∀i: Σ (aⱼ - tⱼ) ≥ 0` для всех префиксов последовательности.

**Пример: Стек с MULTIPOP (через монетки)**

- Назначаем стоимости:
    
    - `PUSH`: **2 монеты**.
        
    - `POP`: **0 монет**.
        
    - `MULTIPOP`: **0 монет**.
        
- **Распределение для `PUSH`**:
    
    - **1 монета** оплачивает фактическое добавление элемента.
        
    - **1 монета** остаётся как кредит **на этом элементе** для его будущего удаления (через `POP` или `MULTIPOP`).
        
- **Проверка**:
    
    - При `POP` или `MULTIPOP(k)` реальная стоимость `tᵢ = k`. Мы оплачиваем её, используя по 1 монете, хранящейся на каждом удаляемом элементе.
        
    - Кредит всегда неотрицателен, так как монета лежит на элементе с момента `PUSH` и до его удаления.
        
- **Вывод**: `a_push = 2 = O(1)`, `a_pop = a_multipop = 0 = O(1)`.
    

#### **2.3. Метод потенциалов**

**Идея**: Вводится **функция потенциала** `Φ(D)`, отображающая состояние структуры данных `D` в неотрицательное вещественное число. Потенциал — это запасённая "потенциальная энергия" для оплаты будущих дорогих операций.

**Определение амортизированной стоимости**:  
`aᵢ = tᵢ + (Φ(Dᵢ) - Φ(Dᵢ₋₁))`, где `ΔΦᵢ = Φ(Dᵢ) - Φ(Dᵢ₋₁)` — изменение потенциала.

**Связь с реальной стоимостью**:  
`Σ aᵢ = Σ tᵢ + Φ(Dₙ) - Φ(D₀)`.  
Если `Φ(D₀) = 0` и `Φ(Dᵢ) ≥ 0` (что обычно выполняется), то `Σ tᵢ ≤ Σ aᵢ`.

**Пример: Стек с MULTIPOP (через потенциалы)**

- **Выбираем потенциал**: `Φ(S) = количество элементов в стеке = |S|`. Очевидно, `Φ ≥ 0`.
    
- **Вычисляем `aᵢ`**:
    
    - `PUSH`: `tᵢ = 1`. `ΔΦ = |S'| - |S| = +1`. `aᵢ = 1 + 1 = 2`.
        
    - `POP`: `tᵢ = 1`. `ΔΦ = -1`. `aᵢ = 1 - 1 = 0`.
        
    - `MULTIPOP(S, k)`: пусть `k' = min(k, |S|)` реально удалённых элементов. `tᵢ = k'`. `ΔΦ = -k'`. `aᵢ = k' - k' = 0`.
        
- **Вывод**: Все амортизированные стоимости `O(1)` → `Σ tᵢ = O(n)`.

### **3. Пример: Динамический массив (вектор)**

**Операция `PUSH_BACK`**: Если массив полон (size = capacity), выделяется новый массив большего размера (например, в `k=2` раза), и все элементы копируются.

**Пиковая стоимость**: `O(n)` при переполнении.  
**Амортизированная стоимость**: `O(1)`.

**Доказательство методом потенциалов**:

- **Состояние**: `size` — текущее число элементов, `cap` — текущая ёмкость.
    
- **Потенциал**: `Φ = 2 * size - cap`. Условие `Φ ≥ 0` выполнено, так как при нашей стратегии удвоения всегда `size ≥ cap/2`.
    
- **Анализ**:
    
    1. **`PUSH` без расширения** (`size < cap`):
        
        - `tᵢ = 1` (вставка).
            
        - `ΔΦ = 2*(size+1) - cap - (2*size - cap) = 2`.
            
        - `aᵢ = 1 + 2 = 3`.
            
    2. **`PUSH` с расширением** (в момент `size = cap = n`):
        
        - `tᵢ = n + 1` (копирование n элементов + вставка нового).
            
        - Новый `cap' = 2n`.
            
        - `Φᵢ₋₁ = 2n - n = n`.
            
        - `Φᵢ = 2(n+1) - 2n = 2`.
            
        - `ΔΦ = 2 - n`.
            
        - `aᵢ = (n+1) + (2 - n) = 3`.
            
- **Вывод**: В любом случае `aᵢ = 3 = O(1)`.

### **4. Применение: Очередь на двух стеках**

**Структура**: Очередь моделируется двумя стеками: `in` (для добавления) и `out` (для извлечения).

- `ENQUEUE(x)`: `PUSH(in, x)`.
    
- `DEQUEUE()`: если `out` пуст, **перекладываем все элементы из `in` в `out`** (каждый через `POP(in) -> PUSH(out)`), затем `POP(out)`.
    

**Амортизированный анализ методом потенциалов**:

- **Потенциал**: `Φ = |in|` (количество элементов в стеке `in`).
    
- **Анализ**:
    
    - `ENQUEUE`: `tᵢ = 1` (простой `PUSH`). `ΔΦ = +1`. `aᵢ = 2`.
        
    - `DEQUEUE`:
        
        1. Если `out` не пуст: `tᵢ = 1` (простой `POP`). `ΔΦ = 0` (`in` не меняется). `aᵢ = 1`.
            
        2. Если `out` пуст: нужно переложить `m` элементов из `in`. `tᵢ = 2m + 1` (`m` раз `POP(in)`, `m` раз `PUSH(out)`, 1 раз `POP(out)`). `ΔΦ = -m` (после операции `in` пуст). `aᵢ = (2m+1) + (-m) = m + 1`.
            
            - Заметим, что перед этой операцией потенциал `Φ = m`. Поэтому можно считать `aᵢ = 3`, если "занять" у накопленного потенциала.
                
- **Вывод**: Амортизированная стоимость `ENQUEUE` и `DEQUEUE` — `O(1)`.
