### **1. Определение и основная идея**

**Splay-дерево** — это **самобалансирующееся** бинарное дерево поиска **без явного хранения баланс-фактора** (как height или priority).

**Ключевая идея (принцип локальности):**

- После любой операции (`Find`, `Insert`, `Erase`) с элементом `X` выполняется специальная операция **`Splay(X)`**.
    
- `Splay(X)` **"поднимает"** узел `X` в корень дерева с помощью последовательности поворотов.
    
- **Цель:** Часто используемые элементы оказываются близко к корню, что ускоряет доступ к ним (принцип **"кэширования"**).
    

**Важно:** Splay-дерево **не гарантирует** сбалансированность в каждый момент. Но **амортизированная** сложность операций составляет `O(log n)`.

___
### **2. Операция `Splay(x)`**

Операция выполняется, пока узел `x` не станет корнем. Используются **три типа шагов (zig, zig-zig, zig-zag)** в зависимости от позиции `x`, его родителя `p` и деда `g`.

**Обозначения:**

- `x` — поднимаемый узел.
    
- `p` — родитель `x`.
    
- `g` — родитель `p` (дед `x`).
    

##### **Шаг 1: Zig (одиночный поворот)**

**Выполняется, когда `p` — корень дерева.**

- Если `x` — **левый** ребёнок `p` → правое вращение вокруг `p` (как в AVL).
    
- Если `x` — **правый** ребёнок `p` → левое вращение вокруг `p`.
    

```text
    p          x
   / \   ->   / \
  x   C      A   p
 / \            / \
A   B          B   C
```

##### **Шаг 2: Zig-zig**

**Выполняется, когда `x` и `p` оба **левые** или оба **правые** дети.  
Сначала поворот вокруг `g`, затем вокруг `p`.

- **Случай LL (x — левый ребёнок p, p — левый ребёнок g):**
    
    1. Правое вращение вокруг `g`.
        
    2. Правое вращение вокруг `p`.
        
```text
      g            p           x
     / \          / \        /   \
    p   D  ->    x   g  ->  A     p
   / \          / \ / \          / \
  x   C         A B C D         B   g
 / \                               / \
A   B                             C   D
```

##### **Шаг 3: Zig-zag**

**Выполняется, когда `x` и `p` — разносторонние дети** (x — левый, p — правый или наоборот).  
Сначала поворот вокруг `p`, затем вокруг `g`.

- **Случай LR (x — правый ребёнок p, p — левый ребёнок g):**
    
    1. Левое вращение вокруг `p`.
        
    2. Правое вращение вокруг `g`.
        
```text
    g              g              x
   / \            / \            / \
  p   D   ->     x   D   ->     p   g
 / \            / \            / \ / \
A   x          p   C          A B C D
   / \        / \
  B   C      A   B
```

### **3. Теорема о времени работы операции `Splay` (аморт. анализ)**

**Утверждение:** Амортизированное время операции `Splay(x)` в дереве с `n` узлами есть **`O(log n)`**.
#### **1. Потенциал**

Вводим **потенциал** всего дерева `Φ`, который помогает "копить" оплату за быстрые операции и тратить её на медленные.

**Определение потенциала:**

- Пусть для каждого узла `v` определён его **размер** `size(v)` — количество узлов в поддереве с корнем в `v`.
    
- Определим его **ранг**: `r(v) = log₂(size(v))`.
    
- **Потенциал дерева** `Φ = Σ r(v)` (сумма рангов по всем узлам `v` в дереве).
    

**Свойства:**

- `0 ≤ Φ ≤ n log n`.
    
- После `Splay` потенциал может как увеличиться, так и уменьшиться.
    

#### **2. Амортизированная стоимость**

Пусть `t` — реальное время шага (число поворотов × `O(1)`), `ΔΦ` — изменение потенциала.  
**Амортизированная стоимость шага:** `a = t + ΔΦ`.

**Нам нужно доказать, что:**

1. Амортизированная стоимость **одного шага (Zig, Zig-zig, Zig-zag)** есть `O(1)` (точнее, ≤ `3(r'(x) - r(x))` для Zig-zig/zig-zag и ≤ `1 + 3(r'(x) - r(x))` для Zig, где `r(x)` — ранг до шага, `r'(x)` — после).
    
2. Тогда, суммируя по всем шагам `Splay`, амортизированная стоимость всей операции будет:  
    `A ≤ 1 + 3(r(root) - r(x)) = 1 + 3*log(size(root)/size(x)) ≤ 1 + 3*log n = O(log n)`.
    

#### **3. Разбор случаев (схема доказательства)**

##### **Случай Zig (p — корень)**
`ΔΦ = (r'(x) + r'(p)) - (r(x) + r(p))`
`a = 1 + (r'(x) + r'(p)) - (r(x) + r(p))`


```text
    p          x
   / \   ->   / \
  x   C      A   p
 / \            / \
A   B          B   C
```

- **Размеры:**
    
    - `size'(x) = size(p)` (всё поддерево осталось тем же).
        
- Следовательно:
    
    - `r'(x) = r(p)` (т.к. `size'(x) = size(p)`).
        
    - `r'(p) ≤ r'(x)` (т.к. `size'(p) < size'(x)`).
        

Подставляем в формулу для `a`:

```text
a = 1 + (r'(x) + r'(p)) - (r(x) + r(p))
  = 1 + (r(p) + r'(p)) - (r(x) + r(p))
  = 1 + r'(p) - r(x) ≤ 1 + r'(x) - r(x) ≤ 1 + 3(r'(x) - r(x))
```

##### **Случай Zig-zig**

`ΔΦ = (r'(x) + r'(p) + r'(g)) - (r(x) + r(p) + r(g))`
`a = 2 + (r'(x) + r'(p) + r'(g)) - (r(x) + r(p) + r(g))`

```text
      g            p           x
     / \          / \        /   \
    p   D  ->    x   g  ->  A     p
   / \          / \ / \          / \
  x   C         A B C D         B   g
 / \                               / \
A   B                             C   D
```


1. **Убираем `r(g)`**: `size'(x) = size(g) => r'(x) = r(g)`. Подставляем в формулу для `a`:  
    `a = 2 + r'(p) + r'(g) - r(x) - r(p)`
2. **Используем `r(p) ≥ r(x)`**: 
`a ≤ 2 + r'(p) + r'(g) - r(x) - r(x) = 2 + r'(p) + r'(g) - 2r(x)`
3. **Ключевое неравенство**: Поддеревья `g` (после поворота) и `x` (до поворота) **не пересекаются** и оба лежат внутри нового поддерева `x`. Поэтому:  
`size'(g) + size(x) ≤ size'(x)`
Поделим на `size'(x)`:  
`size'(g)/size'(x) + size(x)/size'(x) ≤ 1`
4. **Свойство логарифма**: Для любых чисел `u`, `v`, если `u + v *≤ 1`, то `u*v ≤ 1/4` 
($\sqrt{ uv }\leq \frac{u+v}{2} \implies uv \leq \frac{u + v}{2}$). Логарифмируем:  
`log u + log v ≤ log(1/4) = -2`.
Применим к `u = size'(g)/size'(x)` и `v = size(x)/size'(x)`:  
`r'(g) + r(x) = log(size'(g)) + log(size(x)) ≤ -2`  
Перепишем: `r'(g) + r(x) ≤ -2 ≤ 2r'(x) - 2`
5. **Подставляем в оценку для `a`** (из пункта 2):  
`a ≤ 2 + r'(p) + r'(g) - 2r(x)`  
Теперь заменим `r'(g)` на оценку из пункта 4: `r'(g) ≤ 2r'(x) - 2 - r(x)`
Получаем: `a ≤ 2 + r'(p) + [2r'(x) - 2 - r(x)] - 2r(x) = r'(p) + 2r'(x) - 3r(x)`
6. **Последний шаг**: `size'(p) ≤ size'(x) => r'(p) ≤ r'(x)`. Подставляем:  
`a ≤ r'(x) + 2r'(x) - 3r(x) = 3r'(x) - 3r(x) = 3(r'(x) - r(x))`

### **4. Основные операции**

#### **`Merge(tree1, tree2)` — Слияние**

**Предусловие:** Все ключи в `tree1` строго меньше всех ключей в `tree2`.

1. Если `tree1 == nullptr`, вернуть `tree2`. Если `tree2 == nullptr`, вернуть `tree1`.
    
2. **В `tree1` найти узел с максимальным ключом.** Выполнить `Splay(max_node)`. Теперь `max_node` — корень `tree1`, у него **нет правого ребёнка**.
    
3. **Подвесить `tree2` как правого ребёнка `max_node`**.
    
4. Вернуть новое дерево с корнем `max_node`.
    

#### **`Split(tree, x)` — Разделение**

**Возвращает:** `(tree1, tree2)`, где `tree1` содержит ключи **< x**, `tree2` — ключи **≥ x**.

1. Если `tree == nullptr`, вернуть `(nullptr, nullptr)`.
    
2. **Найти Lower Bound для `x` (LB)** — узел с наименьшим ключом `≥ x` (через обычный поиск BST). Если такого узла нет (все ключи < `x`), взять узел с максимальным ключом.
    
3. **Выполнить `Splay(LB)`.** Теперь `LB` — корень дерева.
    
4. **Сравнить `root.key` с `x`:**
    
    - **Если `root.key < x`**: Все ключи в дереве меньше `x`. Вернуть `(tree, nullptr)`.
        
    - **Если `root.key ≥ x`**:
        
        - `tree1 = root.left`
            
        - `tree2 = root`
            
        - **Отсоединить** `root.left = nullptr`
            
        - Вернуть `(tree1, tree2)`.
            
#### **`Find(tree, x)` — Поиск**

1. Выполнить обычный поиск BST, сохраняя последний посещённый узел.
    
2. **Если `x` найден**:
    
    - Сделать `Splay(найденный_узел)`.
        
    - Вернуть `true` и дерево с новым корнем.
        
3. **Если `x` не найден**:
    
    - Сделать `Splay(последний_посещённый_узел)`.
        
    - Вернуть `false` и дерево (с ближайшим к `x` элементом в корне).
        

#### **`Insert(tree, x)` — Вставка**

1. `(L, R) = Split(tree, x)`
    
2. **Проверить дубликат:** Если `R != nullptr` и `R.key == x` (т.е. `x` уже существует), вернуть `Merge(L, R)`.
    
3. Создать новый узел `new_node` с ключом `x`.
    
4. **Собрать новое дерево:**
    
    - `new_node.left = L`
        
    - `new_node.right = R`
        
5. Вернуть `new_node` как новый корень. _(Узел `x` автоматически оказывается в корне)_.
    

#### **`Erase(tree, x)` — Удаление**

1. `(L, R) = Split(tree, x)` // В `R` ключи ≥ `x`
    
2. `(M, R) = Split(R, x + 1)` // В `M` только ключи, равные `x` (обычно один узел).
    
3. Удалить узел (дерево) `M`.
    
4. Вернуть `Merge(L, R)`.

### **5. Итог: Сравнение с другими BST**

|Свойство|**Splay-дерево**|**AVL**|**Декартово**|
|---|---|---|---|
|**Балансировка**|Амортизированная, эвристическая|Строгая, детерминированная|Вероятностная|
|**Гарантия**|**Амортизированная** `O(log n)`|**Строгая** `O(log n)`|**Ожидаемая** `O(log n)`|
|**Принцип**|Локальность (поднимает часто используемые)|Глобальная сбалансированность|Случайные приоритеты|
|**Константы**|Малые (нет доп. полей)|Есть доп. поле `height`/`bf`|Есть поле `priority`|
|**Операции**|Всё через `Splay`|Стандартные BST + балансировка|Всё через `Split`/`Merge`|
