1. На цепочках
Храним массив, его элементы - "Бакеты" ==(иллюстрация 1)==
Бакетов k. 
Запрос Insert(key, value)
hash(key) -> {0, ..., N}

Храним элементы в бакетах. Если бакет пустой, кладём туда элемент. Важно, чтобы на один и тот же key возвращалось одно и то же значение.

N%k

Если $k_{1}=k_{2}$,  но $hash(k_{1})=hash(k_{2})$, то это коллизия.


Добавляем элемент в тот же бакет, храним их цепочками.

**Примечание:** *В Java, если длина цепочки >8, она перестраивается в красно-чёрное дерево.*


Как работает **find**:
1) hash(k)
2) Проходится по цепочке, ищет ключ

---

Как работает **Insert**:
1) hash(k)
2)  Добавляем в конец

---

Как работает **Remove**:
1) hash(k)
2) Удаление как в односвязном списке

**Вопрос:** Сколько бакетов нужно?
**Ответ:** Оно обычно пропорционально количеству элементов. 
Вводят loadFactor = $\frac{elementCount}{buck etCount}$
Обычно loadFactor должен быть < 1.

Допустим, это 0,75. Если больше, удвоим число бакетов.

В Java все объекты наследуют от класса Object функцию hashCode().
Возвращает Integer.

**Интерфейс:** Map<K, V>
**Его реализация:** HashMap<K, V>

`Integer a = 42;`
`a.hashCode() // возвращает 42.`

`String text = "abacaba";`

У каждого символа есть код: допустим, у a это 60, у b это 61, и так далее.
Сложим их и домножим на простое число (в Java это 31).

$60*31^6+ 61*31^5 + 60*31^4 + 62*31^3 + 60*31^2 + 61*31^1 + 60*31^0$ - полиномиальное хеширование.

У объекта это не по символам, а по полям. (У каждого из значений полей вызовем функцию hashCode()).

##### **Задача 1.** Есть два множества элементов: A и B.
Хотим построить их пересечение, объединение, xor за $O(|A|+|B|)$.
##### **Решение:** 
Закинем B в хеш-таблицу h.

(Для пересечения)
for (a : A) {
	if h[a] -> C.add(a);
}

(Для объединения)
for (a : A) {
	C.add(a);
}
for (b : B) {
	if !(h[b]) -> C.add(b); 
}

##### **Задача 2.** Есть строка. Как определить, сколько есть подстрок, которые содержат все символы из исходной строки хотя бы по одному разу.

##### Решение. 
(Подстроки различаем только по позиции начала и конца).

Количества подходящих подстрок с i-той позиции.
Если нашли наименьшую такую, прибавим n-l+1 (n - длина всей строки, l - подстроки).

Используем два указателя. 
1 - на начало подстроки
2 - на конец минимальной

Заведём hashmap элементов между указателями. 
Сдвигаем указатель 2 вправо.
За один шаг подсчитали количество подстрок с i-той позиции.

Идём дальше. Двигаем левый указатель вправо, возможно, перестало выполняться условие (все уникальные элементы строки в подстроке), тогда двигаем правый указатель до тех пор, пока не станет выполняться условие или не закончится вся строка.
